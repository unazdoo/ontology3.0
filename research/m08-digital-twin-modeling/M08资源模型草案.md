# M08 资源模型草案

> 状态：研究建议。资源名、Owner 和合同编号均待平台 CR/用户裁决

## 1. 设计原则

1. Published Ontology 和精确数据版本是输入，不由 M08 复制或改写。
2. 业务问题、候选、一次运行、不可变模型版本、消费绑定是不同资源。
3. 发布候选不是 Published 模型；研究验证永不写 T019。
4. 事实、预测和模拟有不同资源身份、权限和存储域。
5. 应用、Agent、Lens 和报告只消费稳定引用，不维护第二套结果或模型端点。
6. Simulation Baseline 只引用 Owner 的不可变事实快照；模拟 delta/result 永远不成为事实。

## 2. 模型治理资源

| 资源 | 定义 | 稳定身份 | 不可变部分 | 可变部分 | 建议 Owner |
|---|---|---|---|---|---|
| Modeling Objective | 一个可评估的业务建模问题及其 I/O、评估协议、人工门和使用边界 | `objectiveId` | 已进入比较的 Objective Revision | Draft 元数据和新 Revision | M08；业务目的由场景 Owner 确认 |
| Candidate Model | 针对同一 Objective 提交的候选解法容器 | `candidateId` | 已提交版本引用和提交证据 | 新候选版本、说明、归档状态 | M08 |
| Experiment | 一次训练/参数试验及其指标、参数、环境和产物引用 | `experimentId` | 完成后的输入、参数、环境、输出和日志摘要 | 运行中状态；失败后仅新建重试 | M08 |
| Evaluation Run | 精确 Model Version×Evaluation Data Transaction×Evaluator 的确定性运行 | `evaluationRunId` | 完成后的全部版本、样本范围、指标和错误 | 运行中状态 | M08；数据事实由 M02 |
| Model Version | 序列化模型、运行代码/API schema 和环境的不可变快照 | `modelVersionId` + content hash | 全部内容、作者、环境、训练/特征版本 | 无；修订产生新版本 | **待裁决**，研究期 M08 |
| Model Submission | 某个 Model Version 进入 Objective 的不可变提交 | `submissionId` | Objective Revision、Model Version、元数据和时间 | Review/Check 作为关联资源演进 | M08 |
| Model Review | 人工评审结论和理由 | `reviewId` | 已提交的单次决定 | Pending 期间评论；决定后不可改 | 评审组；记录由 M08 |
| Model Release Candidate | 经过硬门、只可用于研究/预发布绑定的候选 | `releaseCandidateId` | Model Version、Review、版本说明 | 可撤销/被新候选替代 | **待裁决**；本轮仅 M08 research |
| Model Binding | 稳定模型端口到 Ontology Object/Property 的类型化映射，并指向 Release Selector | `bindingId` + binding revision | 已验证 revision 的映射、类型、单位、selector | 新 revision、候选切换、撤销 | M01 拥有语义目标；M08 拥有模型侧，需 CR |
| Deployment/Runtime Binding | 把 Release Selector 解析到内部运行实现的控制面 | `runtimeBindingId` | 一次解析记录 | 新解析/回退 | 后置；正式 Owner 待裁决 |

`Candidate Model` 是本项目显式资源，避免把算法说明、Model Version、Submission 或 Release 混成一个“模型”。`Model Binding` 也是本项目显式资源；消费者可见稳定 selector 和 Model Version 追溯，但看不到 endpoint、token、credential 或部署拓扑。

## 3. 模拟资源

| 资源 | 定义 | 最低字段 | 建议 Owner |
|---|---|---|---|
| Simulation Baseline | 对精确 Published Ontology/数据/事实快照的不可变引用及克隆范围 | `baselineId`、C033、事实快照/Owner 导出、as-of、schema、hash、权限 | M08 编排；事实仍归 M01/M02/场景 Owner |
| Simulation Case | 一次要回答的 what-if 问题，组合 baseline、parameter set 和 graph | `caseId`、目的、scope、baselineId、parameterSetId、graphId | M08 |
| Parameter Set | 类型、单位、边界、来源类别明确的参数集合 | `parameterSetId`、schemaVersion、value/unit/bounds、ASSUMED/USER_SUPPLIED | M08；业务边界由场景 Owner |
| Composite Model Graph | 不可变的类型化 DAG revision | `graphId`、node/modelVersion、typed ports、unit、time grain、failure policy | M08 |
| Simulation Run | 一次拓扑执行及每节点状态 | `simulationRunId`、精确输入版本、node runs、side-effect audit | M08 |
| Simulation Result | 与 Run 一一关联的模拟输出 | `simulationResultId`、`resultKind=SIMULATION`、outputs、coverage、errors、evidence | M08 |
| Simulation Comparison | baseline、多个 case 或三态的并列比较 | `comparisonId`、列引用、差异规则、不可覆盖标志 | M08；展示由 M07/M06 |

Simulation Baseline 不是 T056，也不能用组合 localStorage、历史 runtime JSON 或目录复制充当完成状态。它必须引用各 Owner 的精确导出和 hash，并在克隆时生成新的隔离运行身份。

Simulation Baseline
  1 -> n Simulation Case

Simulation Run

Simulation Result

## 5. 状态机

### 5.1 Objective

`DRAFT -> RESEARCH_ACTIVE -> REVIEWED_FOR_INITIATION -> ACTIVE -> ARCHIVED`

本轮最高只能到 `RESEARCH_ACTIVE`。`REVIEWED_FOR_INITIATION` 需要正式产品基线和用户裁决；`ACTIVE` 表示模块已立项，不能由内部测试形成。

### 5.2 Candidate/Submission/Review/Release Candidate

```text
Candidate: DRAFT -> VALIDATED -> SUBMITTED -> ARCHIVED
Submission: IMMUTABLE_SUBMISSION -> UNDER_REVIEW -> REVIEW_CLOSED
Review: PENDING_HUMAN_REVIEW -> HUMAN_APPROVED | REJECTED | CHANGES_REQUIRED
Release Candidate: NOT_CREATED -> RESEARCH_RELEASE_CANDIDATE -> REVOKED | SUPERSEDED
```

硬约束：只有 `HUMAN_APPROVED` 的精确 Model Version 可形成 Release Candidate。任何自动 metric/check 都不能替代人工决定。研究 Release Candidate 固定 `published=false`、`productionEligible=false`、`t019WriteAllowed=false`。

### 5.3 Experiment/Evaluation Run

`QUEUED -> RUNNING -> SUCCEEDED | FAILED | CANCELED`

失败或取消后不能原地覆盖；重试形成新 Run，并用 `retryOf`/`supersedes` 关联。

### 5.4 Simulation

```text
Case Revision: DRAFT -> VALIDATED -> READY -> ARCHIVED
Run: QUEUED -> VALIDATING -> RUNNING -> SUCCEEDED | FAILED | CANCELED
Node Run: PENDING -> RUNNING -> SUCCEEDED | FAILED | SKIPPED_UPSTREAM_FAILED
Result: FORMED -> READ_ONLY -> SUPERSEDED | RETAINED
```

部分节点输出可以保留诊断，但只要任一必需节点失败，Result `promotable=false`，不得进入 Release/Binding 或事实域。

## 6. 统一追溯包络

每个 Model/Evaluation/Simulation Run 至少携带：

- C033 `scenarioId/scenarioVersion/scenarioRunId`；M08 研究还携带 `namespace=ofw.m08.research.v1`；
- Objective/Case/Graph/Model Version/Binding Revision 的精确 ID；
- M02 提供的 training/evaluation/runtime data version、exact transaction、T008、quality/C017；
- feature schema、evaluator、metric schema、parameter schema 和 environment version；
- author/submitter/reviewer、形成时间、前序/重试/替代关系；
- input/output hash、状态、coverage、error/reason code；
- evidence location 和权限投影；
- `resultKind`、as-of 与事实引用；
- `factWriteAllowed=false`、`actionWriteAllowed=false`（预测/模拟）。

## 7. Owner 边界

| Owner | 拥有 | M08 只读/提供 | 禁止 M08 接管 |
|---|---|---|---|
| M01 | Published Ontology、Property、Metric、Rule、Action Type、T019；S003 C035 特例 | 提供 Published/Binding 目标；接收模型侧绑定草案 | 不创建/修改 T019，不迁移 S003 特例 |
| M02 | 数据/特征来源、精确版本、质量、T008、C017、脱敏证据 | 向 M08 交付版本化输入；接收运行引用 | 不把模型/参数配置写入管道 |
| M03 | 问数 Agent、问数运行和回答 | 只读已批准 Binding/Result | 不执行正式模型或模拟 |
| M04 | Action Request、提醒、确认、待办、决策摘要 | 拒绝模拟/预测来源；接收正式事实链请求 | 模拟不创建任何 M04 资源 |
| M05 | Agent 定义、Release、Run、生成结果 | 解释模型/模拟证据 | LLM 不评分、不选模、不模拟、不发布 |
| M06 | 报告/仪表盘定义、证据包、T049/C027、正式产物 | 并列展示结果 | 不重算或拥有模型/模拟真值 |
| M07 | Lens、会话、查询、布局、筛选、深链 | 展示三态 source envelope | 不把预测/模拟升级为事实 |
| 平台公共层 | 场景、权限上下文、Checkpoint、发布治理 | 提供隔离与门禁 | 不复制模块真值 |

## 8. 必须通过 CR 的合同

新一级模型资源和编号；正式 Model Version/Release Pointer/Evaluation Run Owner；M01/M08 Binding 拆责；S003 C035 特例迁移策略；三态 source envelope；M04 模拟来源拒绝；M02 特征/评估集交付；M07/M06 展示合同；模拟资源是否进入平台 Published 语义。详见《待用户裁决与CR建议.md》。
