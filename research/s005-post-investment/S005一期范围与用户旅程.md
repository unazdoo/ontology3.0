# S005 一期范围与用户旅程

> 状态：研究推荐，不表示完整建设已获授权

## 1. 一期最小业务闭环

一期建议以“人工复核的投后评价工作台”为目标，不以自动决策或交易为目标：

1. 登记来源快照、哈希、结构和数据截至时间候选；
2. 识别产品/持仓候选身份，展示冲突并由获权用户复核；
3. 选择获批准的产品分类（利率债、短期纯债、中长期纯债、混合一级债基、混合二级债基）、基准、市场同类基金池和评价时点；
4. 先标记范围/数据事实状态，再计算真实可用指标；
5. 分开显示产品表现、本公司实际投资结果、固定收益风险、管理运行质量；
6. 同时展示维度结果、独立风险灯、数据覆盖和结论置信度；
7. 对缺失诚实降级为完整、部分、观察期不足或无法评价；
8. 人工复核事实、公式版本、原因码和证据后，仅保存研究评价记录；
9. 不自动形成 Action Request、提醒、审批、负责人待办或交易指令。

10. 增加四条研究轨道：全市场与入池横评、准入持续合规、池内选中/未选选择归因、交易择时与日常/事后风险监控。它们先以只读研究驾驶舱和证据链实现，不把 Wind 或官方事件直接注册为生产数据资产。

## 2. 四类评价域

| 评价域 | 核心问题 | 一期候选输出 | 不得混淆 |
|---|---|---|---|
| 产品自身表现 | 产品管理结果相对风险、基准和同类如何 | TWR、基准超额、同类位置、波动/回撤、跨周期稳定性 | 不用本公司持仓盈亏代替 |
| 财务公司实际投资结果 | 本公司真实投入资金取得何种结果 | MWR/XIRR、现金流、已实现、未实现、现金收益和勾稽 | 不把资金时点影响归因给管理人，不自动并入产品质量总分 |
| 固定收益风险 | 收益背后承担哪些利率、信用、集中和流动性风险 | 久期/期限、评级/迁移、发行人/行业集中、流动性和事件 | 无穿透数据时只评可见层级 |
| 管理与运行质量 | 管理人和产品运行是否稳定、透明、符合约定 | 身份稳定、披露、估值、风格漂移、重大事件和处置证据 | 不让 LLM 生成正式定性结论 |
| 准入持续合规 | 当前是否仍符合获批范围和公开监管事实 | 管理人事件、合同范围、Wind 分类、最近可见持仓、数据新鲜度 | 只显示符合范围/需复核/无法判断/不在允许范围 |
| 选择与执行 | 入池后为什么选了这些基金、交易执行是否有效 | 选中/未选差异、择时、滑点、费用、现金拖累和操作事件 | 不把未选当负例，不自动创建行动 |

## 3. 四层结论控制

### 3.1 事实状态

一期不设置多级权限、安全或自动阻断门。评价事实只输出“符合范围、需复核、无法判断、不在允许范围”，并显示证据和数据时效。获批投资范围、监管/制度、违约/暂停兑付/赎回受限、估值状态、身份和数据时效仍须观察，但不自动创建动作。

“不在允许范围”只作为事实标签；“无法判断”不等于符合；所有状态必须带原因和来源。规则列表、回溯窗口和人工复核责任待裁决。

### 3.2 维度评分

一期优先输出维度结果和 `scored_coverage`，不默认输出单一星级。缺失维度不得自动重分配权重。Sharpe 纳入风险调整收益子维度，但必须和 Sortino、Calmar、最大回撤、信息比率和固定收益归因并列。研究参数槽位包括：

- `minimum_history_by_metric`；
- `weight_by_category`；
- `score_normalization_method`；
- `peer_minimum_size`；
- `benchmark_priority`；
- `missing_dimension_policy`；
- `score_band_mapping`。

### 3.3 独立风险灯

候选灯包括合规/限额、信用/评级迁移、久期/期限、集中度、流动性/赎回、估值/数据质量、管理人/披露/重大事件。状态候选为绿、黄、红、灰；灰表示无法判断。高评分不得抵销红灯。

### 3.4 结论置信度

置信度衡量证据质量，不衡量产品优劣。候选分项：来源权威性、身份映射、覆盖/时效、估值/现金流勾稽、基准/同类可比性、定性证据、公式/参数可复现性。总体置信度应受关键短板约束，不用平均值掩盖核心缺失。

## 4. 核心用户旅程

### 旅程 A：新快照进入研究区

用户查看来源哈希、工作表/字段变化、缺表和公式错误；只有结构与身份质量通过的范围进入后续候选计算。失败保留证据和修复建议，不覆盖上一版本。

### 旅程 B：选择产品并核对身份

用户从脱敏产品目录进入跨期轨迹，查看代码连续性、名称别名、首次/末次出现和缺期；对冲突作版本化人工确认或拒绝。未确认时保持部分/无法评价。

### 旅程 C：执行评价

用户固定评价日、分类、基准、市场同类基金池、数据版本和参数候选，先看范围事实状态，再看六个域。系统只计算满足数据条件的指标，缺失项显示原因和影响。

### 旅程 D：解释风险与结论

用户并排查看评分、风险灯、覆盖、置信度和证据。风险灯可在没有综合分时独立存在；任何结论均可回到源快照哈希和计算版本。

### 旅程 E：人工复核与历史比较

复核人确认/退回研究记录，记录理由但不改写原计算。随后可比较相邻评价 run 的指标、灯色、状态和数据差异；历史 run 不可覆盖。

### 旅程 F：数据不足

当缺净值、现金流、穿透持仓、评级或管理人主数据时，页面直接给出“部分评价/观察期不足/无法评价”、缺失清单和补数要求，不生成看似完整的总分。

## 5. 一期必须具备

- 不可变来源清单、稳定候选身份、数据质量和结构变化；
- 分类/基准/同类组的人工映射和版本；
- 确定性指标计算、公式/参数版本和证据链；
- 事实状态、维度结果、独立风险灯、置信度和四态降级；
- 10—20 只真实候选产品的无前视历史回放；
- 评价日点时市场同类基金池、入池/可执行池快照和同类趋势图研究夹具；
- 入池持续合规规则/事件时间线，未知不等于通过；
- 交易前决策日志、选中/未选原因码和匹配选择差异；
- 日 NAV/交易资料接入后的择时、回撤、波动、亏损和操作风险监控合同；
- 人工复核、失败原因码和可复算验证；
- 研究结果与正式平台资源的物理/命名空间隔离。
