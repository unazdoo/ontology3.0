# S005 投资快照字段字典

> 状态：候选字段解释，仅供研究；字段含义须由来源 Owner 最终确认
> 依据：79 份 XLSX 的结构化只读导入，核对日期 2026-08-24

## 1. 共同约定

- `snapshot_date` 来自文件名日期，是文件代表的观察时点候选，不自动等于业务日终、估值日或数据截至时间 T008。
- 原表没有稳定的行级事件 ID。研究层建议把“对象候选键 + snapshot_date + source_file_sha256 + sheet_role + source_row_ordinal”作为快照行证据身份，而不是业务对象身份。
- “投资金额”“本年度投资收益”“已实现盈亏”等字段的期间口径必须由来源 Owner 解释；字段名含“本年度”时默认按年累计候选处理，不把周差分直接当作当周现金流或收益。
- `UNLABELED_COLUMN_*` 和 `#NAME?` 按源结构保留；未取得定义前不得改名成业务概念或参与正式计算。

## 2. 投资项目每周简报

粒度候选：单一证券/产品在单一快照日的一条时点持仓记录。79 期均存在，每期 17-28 条。

| 字段 | 类型候选 | 研究解释 | 可用性与限制 |
|---|---|---|---|
| 证券代码 | 标识符 | 产品/证券跨期候选键 | 较强；仍需证券主数据确认份额类别、更名、合并和代码复用 |
| 证券名称 | 文本 | 可读名称/别名 | 不能作唯一键；4 个代码出现多名称变体 |
| 投资分类I级 | 枚举 | 一级投资分类 | 可作来源分类事实；不能自动当同类组 |
| 投资分类II级 | 枚举 | 二级投资分类 | 可作候选细分；需与基金合同/监管分类对账 |
| 区域 | 枚举/文本 | 来源记录的区域属性 | 含义及对象归属待确认 |
| 分支机构 | 枚举/文本 | 来源记录的机构属性 | 含义及是否敏感待确认 |
| 持仓数量 | 数值 | 快照时点数量 | 可算时点数量和相邻差额；差额不等于已确认申赎 |
| 投资金额 | 金额 | 成本/投入金额候选 | 可算时点成本和集中度；成本口径待确认 |
| 本年度投资收益 | 金额 | 年累计收益候选 | 可展示源值和经验证的年内变化；不能代替现金流账或产品 TWR |
| 当前市值 | 金额 | 快照时点估值 | 可算时点暴露、浮盈亏率候选；估值来源/时点待确认 |
| 浮动盈亏 | 金额 | 未实现盈亏候选 | 可作来源时点事实；需与市值、成本和会计口径对账 |
| 现价 | 数值 | 快照时点价格/净值候选 | 可做离散价格轨迹；未证明复权、分红和估值频率，不能直接称收益率 |
| 成本单价 | 数值 | 单位成本候选 | 可作时点来源事实；加权方式待确认 |
| 本年已实现盈亏 | 金额 | 年累计已实现盈亏候选 | 不能据周差分自动生成交易或现金流事件 |
| 细分项目 | 枚举/文本 | 来源业务细分 | 可辅助分类；不是稳定产品身份 |
| 项目负责人 | 敏感文本 | 来源责任信息 | 研究输出不落盘原值；不参与产品评价 |

## 3. 风险监控指标

粒度候选：风险指标定义，而非每只产品的观察值。79 期均存在，每期 1 条。

| 字段 | 研究角色 | 限制 |
|---|---|---|
| 指标 | 来源指标名称 | 仅记录来源已有定义，不自动升级为 S005 Metric |
| 定义 | 来源说明 | 需核对版本和生效期 |
| 计算公式 | 来源公式文本/公式 | 只作证据；不得用字符串执行或替代正式模型 |
| 阈值 / 红、黄、绿 | 来源阈值 | 只作当期来源事实；不直接复制为 S005 风险灯 |
| 统计周期 | 来源周期 | 需区分周报展示频率与底层计算频率 |
| 对应战略焦点行动 | 来源关联 | 不触发 Action Request、提醒、审批或待办 |
| 备注 | 来源说明 | 不作稳定结构化字段 |

## 7. 候选标准化结构

研究层建议使用五个只读候选表，不形成正式 T006/T007：

1. `snapshot_manifest_candidate`：文件日期、SHA-256、大小、结构签名、缺表状态。
2. `product_position_snapshot_candidate`：伪名产品 ID、观察时点、数量、成本、市值、来源累计收益和证据定位。
3. `fixed_income_exposure_snapshot_candidate`：伪名债券/发行人 ID、期限、集中度、组合占比和证据定位。
4. `limit_observation_candidate`：限额定义版本候选、实际值、源状态和证据定位。
5. `identity_match_evidence_candidate`：源键、别名变化、首次/末次出现、冲突状态和人工裁决状态。

每张候选表必须携带 `source_file_sha256`、`snapshot_date_candidate`、`sheet_structure_signature`、解析器版本和质量状态；不得把研究伪名或候选键注册成正式 Ontology 身份。

## 8. 字段质量核验规则

- 53 个字段分别记录数据行数、非空率、数值率、公式格数、源缓存错误数和 artifact 导入错误数。
- 源缓存错误与解析器计算错误分栏，禁止合并成一个“源数据错误率”。
- 产品代码和债券名称候选键按每个快照检查重复；发行人重复是持仓一对多的正常可能形态，不能作持仓键。
- `safeDirectDifferenceFields=[]`：没有任何字段获准把相邻周差分直接命名为交易或现金流。
- 日期间隔不固定；24/78 个相邻间隔不是 7 天，所有时间计算必须使用真实日期。
