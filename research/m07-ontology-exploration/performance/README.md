# M07 性能与规模隔离技术验证

本目录提供 `ofw.m07.research.v1.performance` 的可重复 Node 基准。它使用固定种子的合成数据验证一期候选查询算法，不读取或复制 Published Ontology、S005 业务数据或任何生产数据。

## 运行

前置条件：Node.js 20 或更高版本，不依赖第三方包。为减少垃圾回收时点造成的波动，建议暴露显式 GC：

```bash
cd research/m07-ontology-exploration/performance
node --expose-gc benchmark.mjs
```

默认覆盖写入同目录的 `results.json`。也可只打印结果，或指定输出路径：

```bash
node --expose-gc benchmark.mjs --no-write
node --expose-gc benchmark.mjs --output /tmp/m07-performance-results.json
```

同一机器上的重复运行应得到相同工作负载、正确性结论和结果校验和；延迟与内存会受 Node 版本、系统负载、CPU 调频和后台进程影响。比较结果时必须同时比较 `environment`。

## 工作负载

| 验证项 | 确定性数据和操作 | 样本 |
|---|---|---:|
| 对象目录 | 1,000,000 个合成对象；名称前缀、对象类型、状态、质量筛选及游标分页 | 100 次预热 + 600 次计时 |
| 关系图 | 1,000,000 个节点、每节点 12 条合成有向边；8 个根对象的 1–2 跳展开、类型筛选、5,000 节点硬上限 | 50 次预热 + 300 次计时 |
| 长时序 | 1,000,000 点；质量感知的 min-max 降采样、滚动均值、一阶差分和阈值事件计数，融合为一次全量扫描 | 3 次预热 + 20 次计时 |
| 空间 | 500,000 个 WGS84 合成点；1 度网格索引、精确 bbox 复核、跨日界线范围、2,000 要素返回上限 | 80 次预热 + 400 次计时 |

计时使用单进程、单线程、进程内热数据，不包含 JSON 序列化、网络、权限判定、磁盘/数据库、服务排队或浏览器绘制。目录和空间查询的 `count` 是匹配总数，返回 ID 受上限控制；关系图达到上限时设置 `truncated`。

## 硬门

以下门槛是本隔离研究夹具的失败关闭条件，不是生产 SLO：

| 门 | 上限 |
|---|---:|
| 全部数据与索引构建 | 30,000 ms |
| 100 万对象目录查询 p50 / p95 | 20 / 50 ms |
| 1–2 跳关系图展开 p50 / p95 | 20 / 50 ms |
| 100 万点时序融合变换 p50 / p95 | 150 / 250 ms |
| 50 万空间点范围查询 p50 / p95 | 20 / 50 ms |
| 进程峰值 RSS | 768 MiB |

任一门失败时进程退出码为 `1`，但仍写出 `results.json` 供诊断。结构正确性先于计时验证：目录过滤与排序、图节点去重/上限、时序缺失传播/桶数、全球及跨日界线空间查询必须全部通过；否则直接失败且不生成误导性的通过结论。

## 结果解释边界

- 该验证只能证明指定硬件和 Node 运行时下，确定性内存数据结构的算法可行性。
- 它不证明 M01/M02 查询合同已实现，也不证明数据库、搜索引擎、GIS 服务或生产 API 能达到相同结果。
- 它不覆盖并发用户、多租户权限、冷热缓存、版本/证据拼装、网络传输、序列化、取消/超时、故障恢复和 UI 布局/绘制。
- 生产门需要在正式产品基线冻结并确定技术栈后，使用权限过滤后的 Published 数据分布、目标部署规格以及冷/热缓存和并发矩阵重新制定。
- 本结果属于“隔离确定性合成技术验证”，不能作为 M07 正式立项、验收通过或生产容量承诺。
