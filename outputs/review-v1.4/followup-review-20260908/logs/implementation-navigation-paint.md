# v1.4 导航闪现与重复适配清理

## 原因与修改

平台提供一级、二级导航，复用的专业页面同时保留独立导航。此前`adaptFrame`在iframe的`load`事件之后注入九段样式，隐藏模块导航并调整网格。非关键资源尚未加载完成时，模块业务界面已经能渲染，因此有机会先绘出内层导航，再突然消失。

这是展示职责和适配代码重复，不表示可以直接删除整个iframe或模块业务界面。本轮实施：

- 删除Shell里的`frameAdapterCss`及九段内联样式定义，移除旧`ofw-v131-shell-adapter`注入。
- 合并公共滚动、网格和导航规则到唯一的`composite/shared/frame-presentation.css`，模块差异仅保留必要规则。
- v1.4运行装配在九个模块HTML的head首部加入嵌入模式及内联共享样式，早于业务脚本与首次渲染。没有使用固定延时、透明iframe或空白遮罩掩盖闪现。
- Shell只保留共享样式的兼容加载入口及业务上下文、滚动恢复等现有职责，不再维护第二套布局样式。
- 独立打开模块时不启用嵌入模式，专业页自身导航仍可使用；平台嵌入时不参与布局。冻结历史文件未修改，没有直接删除仍被模块逻辑引用的DOM节点。

产品变更位于实施目录`designs/prototype-work/v1.4/`中的：`runtime/start.mjs`、`runtime/frame-presentation.mjs`、`composite/shared/frame-presentation.css`、`composite/s001-e2e-integration/app.js`。所有修改仍未提交，未合并、部署或覆盖独立审查目录。

- 为稳定暴露`load`时序，测试浏览器追加一个延迟1.2秒返回的非关键图片。修改前在数据、本体、问数、决策、Agent、报告6个模块采集到内层导航可见；同一条件下修改后为0。该故障模拟仅存在测试上下文，不进入产品代码。[before/result.json](before/result.json)
- 单独打开模型页，验证原独立导航仍可见；平台四种视口没有页面横向溢出。[after/width-390.png](after/width-390.png)
- 构建通过，保留现有大包体积提示。[build.log](build.log)

原平台业务回归的两次尝试停在首页截图，超过原14秒等待，未进入模块操作，不计为业务流程通过。保留[inherited.log](inherited.log)和[inherited-retry.log](inherited-retry.log)。截图工具改为暂停截图期间动画并使用60秒采集预算后重跑，第三次停在首页load超时，仍未完成整套业务回归，详见[inherited-final.log](inherited-final.log)。这些等待超时未形成可复现的业务缺陷证据，也不能当作通过；本轮可确认的是116项单元检查、20组导航首帧专项和构建通过。
