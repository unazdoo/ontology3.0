# 智财问策 v1.5：功能审视与改造依据

参考九张用户提供的 O1–O3、M1–M3、D1–D3 图片。图片仅是设计输入，不构成业务数据或实现指令。代码基线为本工作区当前提交；原型数据和本体身份保持原版本。

## 边界先于页面

- 对象全景：找到对象、理解事实/规则/关系，保存分析范围，进入模型或形成待处理事项。
- 模型与算法：构建方法、计算假设、核验与比较版本、维护候选和当前应用，输出可引用结果。核验通过不等于业务目标达成。
- 决策中心：统一接收各业务领域的待处理事项或方案；负责研判、决定、分办、承接、执行和效果复核。事项拥有一个身份和连续办理历史。
- 决策工作台为处理入口，阶段是筛选条件。原“分析复核事项”并入工作台；复核属于同一事项后续阶段。
- 运营总览统计事项状态和进度，不重复提供另一套办理队列。
- “融资方案推演”退出决策中心菜单。既有推演工具保留在对象探索的“比较方案 / 已保存方案”，输出固定模拟附件进入事项。
- 不为每一类业务新增菜单，不为每一阶段复制一个事项，不在界面宣称真实多角色权限或真实交易能力。

## 问题—改进方案—涉及页面—保留能力

| 问题 | 改进方案 | 页面 | 保留能力 |
|---|---|---|---|
| 发现页搜索当前只匹配对象类型，保存的地图探索与对象书签分离 | 企业名称/属性可搜索；发现页可恢复两类已有保存记录 | O1 | 三类主目录、23家企业、产品和持仓，不照图新造实体 |
| 地图到画像再到模型易丢失原探索范围与结果身份 | 保存返回上下文；观察日、分析窗口、范围及结果身份可见 | O2/O3/M1 | 地球地图、关系网络、矩阵、明细、问答、预算、时序、来源 |
| 草稿已核验、发布和当前应用混合；切换栏目清空所选运行 | 独立固定候选/试用/审阅；发布默认不换应用；保留所选版本和运行 | M1/M3 | 可编辑代码、停止/超时恢复、核验、导出、停用、归档 |
| 缺少同口径固定双版本业务比较 | 对象、数据指纹、窗口一致才比较；保存两侧运行及差异 | M2 | 原三类算法与所有原运行，不伪造回测指标 |

| 跟踪状态“完成”含义过宽 | 批准、执行完成、效果复核分别记录；凭证、复核结论和后续处理可追踪 | D3/O3 | 历史办理记录、原固定报告和业务事实 |

## 图片取舍与代码问题

O1：采用任务导向的对象目录、恢复探索；不直接复制银行/借据/项目的示意数量。它们在本体中已有适用层级，保留关联下钻，避免把记录集合当成单个对象。

O2：采用分析视角、窗口和结果身份提示；保留代码四种图表、地图操作、CSV、方案比较、规则依据。图片同时展示地图与多组金额容易让来源口径混淆，现有原台账与构造融资明细继续分别标识。

O3：采用事实、预警、模拟、办理进展分层及直接进入相关事项。图片 10-08 的实际资金变化没有现有数据支持，不复制该剧情；无后续证据时只显示效果待复核。保留产品/持仓/部门预算/银行等通用画像能力。

M1：采用业务问题、负责人、当前版本、候选与应用位置的组织方式；目标继续支持新增、归档，不能只有三张融资卡片。

M2：采用同对象、同快照、同窗口比较与代价说明。图片“A/B/C”人工方案不等于代码算法输出；采用实际计算结果。不同窗口或数据版本不能只靠“已核验”标签并排作结论。

M3：采用独立候选试用和当前应用、审阅记录、固定引用。不显示尚未发生的真实上线、业务改善或使用反馈。代码发布自动切换当前应用需拆开。

D1：采用阶段队列与排序原因，但不直接照搬“融资方案推演 / 分析复核事项”的并列菜单。后两者分别是分析工具与事项阶段。筛选来源和负责人可用，未接入登录身份时不称“待我处理”。

D2：采用固定附件、来源核对、决定与分办；详情的主操作随事项阶段变化。批准只形成待承接任务，不记成执行完成。原生审批继续使用原校验，不能绕过。

D3：采用执行凭证和独立效果结论。执行记录不自动修改余额/成本/评分。缺少后续业务数据时选择“依据不足”；“未达成”仍待处理，可发起补充事项或重开，原记录保留。

## 每类页面的操作契约

| 页面 | 核心问题 | 主操作与结果 | 异常恢复 |
|---|---|---|---|
| 对象发现 | 从哪个对象或已存工作继续？ | 搜索/恢复，进入真实对象或原探索状态 | 空结果清筛选；快照/方案缺失提示恢复来源 |
| 企业探索 | 哪些对象需要进一步分析？ | 选企业/分析范围，保存探索或生成固定方案 | 不适用范围明确列出；不自动替换版本 |
| 对象画像 | 事实、提示和办理到哪一步？ | 查看来源、使用模型、打开关联事项 | 监控读取失败重试；后续效果证据不足保留待复核 |
| 模型目标 | 要解决什么问题，采用哪个方法？ | 配置草稿或使用明确版本 | 未保存修改可继续、保存或放弃 |
| 核验/比较 | 输出可信且同口径吗？ | 核验、固定候选、双版本计算与差异记录 | 代码失败/超时停止；范围/窗口不一致先纠正 |
| 发布与应用 | 哪个版本发布、哪个应用、哪个试用？ | 审阅后发布，独立切换应用或停用试用 | 版本不可覆盖；停止试用保留历史结果 |
| 事项工作台 | 下一件需要处理什么？ | 按阶段/来源/负责人筛选，打开同一事项 | 零结果可清筛选；原事项异常进入原恢复操作 |
| 事项详情 | 当前阶段应作什么决定？ | 研判→批准→承接→登记执行→效果复核 | 退回、拒绝、补充、重开保留原因；禁止跳阶段 |
| 运营总览 | 整体办理是否受阻？ | 汇总阶段，返回工作台处理对应事项 | 未知状态保留原标签和来源入口 |

## 验证边界

在独立 CDP4596 浏览器使用新的本地记录验证，不修改用户预览存储。验证对象搜索/恢复/回跳、模型候选及发布隔离、固定比较、跨模块结果送审、批准与执行/效果的隔离、异常恢复，以及现有 npm test / build / verify:current。所有新证据位于本目录。原型中的人工登记仅表明本地记录，不代表外部材料已经自动验证。
