# v1.1 冻结基线对照与补齐

日期：2026-09-06。当前修改对象：v1.3.2。基线：`designs/prototype-releases/v1.1.0`，保持只读。

## 结论

v1.1 的主要价值不仅是界面，还包括配置可追溯、原结果可回看、决策能够处理到具体待办，以及正式报告的固定正文、伴读和独立核验。

当前 M01—M06 大量复用 v1.1 的真实页面，不能仅因外层导航变化就认定功能整体丢失。本轮按入口 HTML 实际加载的脚本、冻结版优化说明、模块功能设计和浏览器点击交叉核对。

## 已补齐

| 项目 | 对照发现 | 本轮处理 |
| --- | --- | --- |
| 问数设置 | v1.1 的配置、领域绑定、能力工具及运行记录仍存在于 `#/agent`，但当前 Shell 没有入口 | 恢复“问数设置”，复用原配置界面；不新增第二套 Prompt 或语义定义 |
| Agent 配置资源 | 基线提供 Prompt、Skill、Tool 的详情、版本与差异，当前导航只保留目录/运行/证据 | 恢复“配置资源”，原配置版本链直接可达 |
| Agent 协作编排 | 基线有顺序、并行和确定性分流模板，创建与验证能力被藏在隐藏的模块导航中 | 恢复“协作编排”和创建入口；既有合同不兼容仍保留草稿/阻断，不假装可以发布 |
| 历史会话与导出 | 基线业务问数会保留历史并可导出，新增模型问数只保存临时页面变量 | 在历史会话中增加模型问数快照；固定对象、结果、版本与证据，保留成功/失败/取消状态，支持 CSV 导出和跨模块后回看；不储存整份模型运行状态 |
| 历史结果加入报告 | 从其他业务域提问或回看旧问题后，报告可能按当前模块的场景保存；基线 `historyRuns` 也没有被正确读取 | 按选中运行 ID 解析历史，缺失时不借用当前答案；根据答案业务域及固定上下文写入对应报告，保留原版本；不按当前运行重算历史答案 |
| 决策处理入口 | 新概览只有状态展示，已分办/执行中的记录无法就近进入具体待办 | 直接打开原有申请、决策事项、负责人待办与全链路追溯，增加返回追踪入口；继续由原决策模块处理状态 |
| 决策状态准确性 | 取消可能显示成已分办；逾期覆盖执行阶段；修改后的负责人和截止时间可能被原确认值覆盖；计数与筛选集合不一致 | 区分结束、失败和执行；逾期作为独立标记；以当前待办为准；执行/结束/关注的统计与筛选同口径 |
| 详情面包屑与工作区层级 | 当前面包屑只显示任务名，弱化了基线的具体页面定位；配置页出现无关的对象结果工具栏 | 恢复可见详情标题；配置、模板、报告阅读等页不插入无关的对象分析条；不重载 iframe |

## 确认保留，不重复建设

- **报告创建、报告定义与模板没有丢失。** 冻结版入口实际加载 `canonical-app.js`，其路由就是 `#/catalog`、`#/create`、`#/definitions`。保留在目录中的旧 `app.js`/`s003-app.js` 路由不是当前入口依据；最初的路由疑点经实际点击排除。
- **正式报告伴读与自动核验没有丢失。** 继续使用基线的报告问答、固定证据、五阶段核验和独立 Agent/规则职责。浏览器实际执行问答与核验，核验前后正式正文源文件保持相同，正文 iframe 不重建。
- **数据工程的来源/快照/管道/运行和本体的 Draft/Published 层级继续复用。** 原有数据成员、精确版本及下游消费链不为本轮另建副本。
- **基线业务问数的视图、语义资源和既有历史保留。** 新增模型历史单独标识，不伪造为原生正式问数运行。
- **当前 v1.3.2 的对象探索、模型目标、跨模块报告草稿和新工作上下文继续保留。** 本轮为增量补齐，不回退整套产品结构。

## 不机械恢复

- 不恢复重复的模块内导航；可用入口并入现有 Shell。
- 不恢复固定“全链路已完成”的展示来代替真实运行证据。
- 不把模型优化能力迁回本体管理；v1.1 正式模型和正式评分仍作为只读基线。
- 不新增角色权限系统、生产编排、真实金融执行或额外审批层级。
