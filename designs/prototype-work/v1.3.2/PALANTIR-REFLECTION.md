# Palantir 对照反思

## 参考范围

本轮对照了用户提供的本地资料：Foundry 2022 Operating System Demo、Ontology: Your Business as Code、Ontology Governance、Foundry 21 Launch、Ontology-Driven Agents、Speedrun E2E Workflow 及系统截图；同时复核 Palantir 官方 Ontology、Object Explorer、Quiver、Workshop Application State、Modeling Objectives 和数据血缘文档。

## 已吸收的产品原则

1. **对象是跨应用复用边界。** M02 的来源与快照进入 M01 的对象、关系和指标，再由问数、探索、模型、驾驶舱和报告消费，不让每个页面重新解释数据。
2. **发现与分析分层。** M07 的 `#discover` 负责搜索、筛选和建立对象集；`#explore` 复用同一对象集进入对象全貌、关系、时序、地图和对比 Lens。
3. **模型围绕业务目标组织。** M08 首先展示业务问题、输入、输出、当前正式模型、最近评测和下一步，再下钻模型实现与技术证据。
4. **应用状态贯穿工作流。** `WorkspaceContext` 将对象集、当前对象、时间、结果视图、版本和证据确定性地传到 M03、M05、M06、M07、M08 与 Dashboard。
5. **操作界面优先于说明。** 首页右侧是可点击功能入口；M07、M08、决策运营和经营控制塔均直接呈现任务、状态和下一步，不使用“增量说明”或静态成功卡片代替功能。
6. **代码与低代码共享模型身份。** M08 的 Python IDE、README、测试、运行、分支、提交、标签和候选版本与同一模型目标、DataVersion 和语义合同绑定。

## 反思后完成的修正

- 首页三圆几何固定，切换只改变高亮与右侧入口，移除造成抖动的整体重排。
- 将 M07 首次进入空白问题修正为“资源就绪后再下发上下文”，并区分过滤对象集与显式选择对象集。
- 将 Dashboard 业务视图切换从 iframe 重建改为原位重挂载集成，五个业务驾驶舱之间切换不增加 frame load。
- 将 M07 → M08 改为直达对应模型目标工作台，完成后可带结果返回原对象、Lens 和时间范围。
- 将投后评价运行 ID 从首屏移入折叠证据，主界面只显示当前评价状态、覆盖和缺失原因。
- 移动端隐藏架构圆中的英文长标签，复杂表格改为卡片或纵向信息块，避免缩小后不可读。

## 尚未照搬的 Palantir 能力

- 未增加权限、审批、环境、部署和运维控制台；本期只保留直接产生用户价值的业务能力。
- 未建设通用低代码页面编辑器、生产级 Ontology SDK 或远程 Git 平台。
- 未把所有模型结果聚合为综合分；补充模型继续保持独立业务问题和结果身份。
- 未把 synthetic 评测结果描述为真实模型有效性结论。

## 最终判断

当前候选已达到本轮原型目标：平台以对象、目标和共享应用状态组织功能；首页、真实模块、探索、建模和驾驶舱属于同一 Shell；五个业务域可以在同一原型内连续运行并回到证据。其产品架构具备扩展到新对象类型、新模型目标、新消费者和新业务驾驶舱的明确边界。

该判断仅指高保真原型的功能架构与交互完成度，不代表生产实施、模型正式有效性或用户验收结论。
