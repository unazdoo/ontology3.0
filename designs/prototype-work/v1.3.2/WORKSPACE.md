# v1.3.2 UX 重构候选工作区

本目录建设 `v1.3.2-rc.1` UX 重构候选。父版本为只读的 v1.3.1，`v1.2.0` 与冻结的 `v1.1.0` 同样保持不变。`acceptanceReady=false`。

## 唯一入口

`composite/s001-e2e-integration/index.html`

```bash
M08_PORT=4373 OFW_STATIC_PORT=4372 node composite/start-candidate.mjs
```

本候选新增的重点是工作上下文、对象/结果身份和窄屏操作体验；生产权限、审批和部署能力不在范围内。

2026-09-06 的对照完善记录见 `V12-PARITY-AUDIT.md`。当前走查服务使用静态端口 4382、模型端口 4383，未停止原有 4362/4363 服务。

入口保留一套 Shell。M01—M06 继续加载 v1.2 使用的真实业务页面；M07、M08 和 Dashboard 是本候选的选择性本地重构，不复制父版本整棵目录，也不增加第二套平台 Shell。

## 本轮重构

- 首页保留三域架构，右侧恢复真实功能入口。能力域切换只更新高亮和入口内容，不移动架构、不重载 iframe。
- 全局 `WorkspaceContext` 统一保存对象集、当前对象、时间范围、对比基准、结果视图、数据版本、语义版本和证据引用。问数、探索、模型、驾驶舱和报告在原位同步该状态。
- M07 重构为“业务对象探索”：`#discover` 用于对象发现，`#explore` 提供对象目录、对象全貌、关系网络、时序分析、地图和对比分析六种 Lens。
- M08 重构为“模型目标与优化”：目标目录、模型与代码、评测对比、候选观察、发布与消费五个任务页围绕同一业务目标运行。Python IDE、README、测试和 Git 式版本记录从模型详情下钻进入。
- Dashboard 重构为经营控制塔。五个业务驾驶舱在同一目录下组织，具体业务视图内可查看正式、候选、影子、模拟和差异；目录不提供“模型结果”按钮。
- M02 按数据源、快照、管道、数据资产组织；M01 按对象、关系、指标和下游使用组织；M03 保留 51 个推荐问题、五步回答动画和行动申请；M04 提供决策工作台与运营驾驶舱；M05/M06 读取同一工作上下文。

## Palantir 对照原则

本轮吸收了本地 Palantir 资料及官方文档中的产品组织方式，但不复制其界面：

- Ontology 作为数据、对象、关系、模型结果和应用的共同语义层。
- Object Explorer 负责对象发现，复杂分析进入共享对象集与多 Lens 工作台。
- Modeling Objective 作为模型、数据、评测、版本和消费的业务问题中心。
- Application State 让对象、时间和结果身份在页面与智能能力之间连续传递。
- 技术身份与版本指纹进入折叠证据区，主界面优先呈现业务问题、状态和下一步。

## 验证边界

最终 Chrome 回归实际执行 S001—S005 的数据、语义、评测、候选、三段 Shadow、复评、Release Candidate、Binding 和压力模拟。S003 正式 1.0.2 模型与 21 家企业正式结果未变；M04 对 PREDICTION、SHADOW、SIMULATION 保持 `NON_FACT_SOURCE_REJECTED`，外部副作用为 0。

本候选不代表模型有效性已经正式证明、生产上线完成、用户评审通过或一期验收通过。
