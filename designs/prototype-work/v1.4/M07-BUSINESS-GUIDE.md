# M07 业务全景使用说明

M07 将本体连接起来的业务数据、判断逻辑、关联对象和业务行动，组织为业务人员可以顺着阅读和处理的对象全景。

## 建议先体验的路径

1. 从平台左侧进入「业务全景」，搜索「环保测试公司4」，打开对象。
2. 查看融资余额、平均融资成本、融资笔数、风险评分和红灯。每项事实显示自己的截至日。
3. 在「需要关注的业务问题」查看融资成本规则与债务风险判断，点「查看判断依据」阅读指标来源、口径和来源精度。
4. 在「关联业务」进入融资明细集合，继续找到优先协商银行；也可以打开负责人或规则。关联对象与原对象集是两个概念，下探不会自动改变分析范围。
5. 在「可采取的行动」进入已有融资优化待办，或专项风险处置待办。原决策中心负责承接、执行、记录进展、完成和审批。
6. 点平台上方「返回业务全景」，读取原决策中心的最新事项状态和办理反馈。刷新后仍可继续查看。
7. 点「加入业务报告」，在报告中心打开草稿，编辑分析文字、预览、导出 HTML。「返回来源」恢复原对象、对象集、时间和视图。

原型中的公司名称、地理布点和业务操作均用于本机演示。记录待办完成不代表银行已实际执行融资调整。

## 页面各部分回答什么问题

| 页面内容 | 业务人员关心的问题 | 主要内容 |
| --- | --- | --- |
| 当前业务情况 | 这个对象目前怎么样？ | 余额、成本、预算执行、持仓观测、风险分档等适用事实 |
| 需要关注的业务问题 | 为什么需要关注？ | 已发布规则的判断条件、实际指标、正式风险评分与分档；预算超支及计算依据 |
| 关联业务 | 涉及哪些业务和参与方？ | 集团、融资明细、金融机构、负责人、产品与持仓等已登记关系 |
| 可采取的行动 | 下一步能做什么？ | 进入原有审批或待办、围绕对象提问、加入报告 |
| 办理进展与业务结果 | 谁在处理，做到哪里？ | 原决策中心的责任人、期限、办理状态、最新进展和完成反馈 |

目录优先呈现企业、集团融资、预算单元、申请主体、产品、持仓和投资组合。规则、负责人等内容从相关业务对象下探，不与主要业务对象混排为目录主线。

## 数据、事件和判断依据来自哪里

- 融资余额、成本和融资笔数来自原融资台账的汇总；融资成本按余额加权。融资判断来自本体中已发布规则及其原求值结果，M07 不自行修改阈值或重新生成审批依据。
- 风险评分和红黄绿灯来自正式债务风险评估结果。红灯属于真实的业务关注状态，与「数据质量不足」没有同一含义。
- 预算金额、实际执行和执行率来自年度预算记录。执行率为实际执行除以预算金额；信息科技费用的 105.4% 表示超支 5.4 个百分点。
- 投资历史来自已有持仓观测。持仓 B 有 79 个实际观测时点，可以按日期查看变化。
- 「事件」表示已登记的预算异常或规则判断等。融资规则记录中的日期表示数据截至日，不代表异常在那一天首次发生。
- 「判断依据」是支撑业务结论的指标、计算口径、规则说明和截至日。主页面不要求业务人员理解技术版本编码；交接报告和其他模块时仍保留来源身份。

同一家公司可同时拥有融资事实和风险评估结果，两类事实仍保留自己的来源。页面顶部「业务视角」用于选择继续问数或模型分析的业务域；对象全景可同时呈现该企业的相关业务情况。

## 为什么不再显示资源质量或资料缺失

M07 面向业务人员。数据完整性、来源核实、身份映射等准备工作由上游的数据工程和本体管理承担。

本轮目录选择已准备好的代表对象，移除了资料补齐剧情、未核实发行人/管理人候选对象和资料完整度时序；不补零、不编造值、不把不完整结果改成「正常」。企业只有风险评估业务时，就呈现风险事实，不展示一张空的融资卡片。

预算超支、风险红灯、待审批、办理中等业务状态继续保留。银行的「协商备选」表示业务协商顺序中的参与方，并非机构信用评级或技术质量评价。

## 时序、地图和比较如何使用

| 工具 | 何时出现 | 使用方法 |
| --- | --- | --- |
| 查看指标变化 | 当前对象有多个实际业务观测时点 | 在对象全景中进入；调整日期或刷选范围，查看该对象的历史指标和区间事件 |
| 查看企业分布 | 当前企业具有演示城市布点 | 在企业全景中进入，查看当前范围内的企业及关系；地图明确标识演示位置，不能作为注册地址 |
| 选择同类对象比较 | 同类型对象之间存在共同业务指标 | 勾选至少两个对象，再开始比较；只显示共有口径，逐行标注截至日 |
| 查看业务关系 | 存在已登记业务关系 | 打开关系图并点选节点；图中心与当前节点分别显示，需要时显式加入分析对象集 |

具有一个静态截至日的企业，不因存在一个数值就显示时序入口。贷款申请主体没有适用的业务时序或位置时，不显示相应入口。

静态快照与区间观测分开：例如选择 2026 年历史区间，2025 年末的风险评分仍会标为「静态快照、不在所选区间」，不会被解释为 2026 年观测。不同规则中的「规则指标值」不能仅因单位都是百分比就混合比较。

## 与其他模块如何衔接

| 模块 | 职责与衔接 |
| --- | --- |
| M02 数据工程 | 准备业务事实，维护接入、版本、质量与来源；M07 展示可用于业务理解的结果 |
| M01 本体管理 | 定义对象、关系、指标、规则和行动类型；M07 通过业务事实与关联业务呈现其成果 |
| M03 智能问数 | 「围绕此对象提问」只带当前对象，不把目录里的所有企业、预算和产品混入问题范围；可返回全景 |
| M08 模型目标与优化 | 沿用原「继续分析」入口，把对象、时间、来源交给模型；候选或模拟结果继续独立标识 |
| M05 Agent 应用 | 保留原业务解释与应用职责；本轮未新建一套解释或编排系统 |
| M04 决策中心 | 唯一的原审批与待办办理入口；M07 读取既有事项并精确打开相应申请或待办 |
| M06 报告中心 | 接收带原始数值和截至日的内容块，负责编辑、预览、导出和返回来源 |

本轮没有另建一套「M07 本地任务」。已有事项直接复用，不会因反复点击产生重复申请。没有已登记事项的对象，通过适用的问数、分析和报告路径继续工作；预算和贷前对象也不会被强行套入融资审批链。

## 办理完成为什么没有让红灯变绿

「完成复核/完成待办」是处理过程的事实；「融资成本下降/预算改善/风险降低」是经营结果的事实。两者必须分别记录。

M07 回读办理反馈，但不会因完成按钮自动降低成本或改变风险分档。下一期正式业务数据或正式评估更新后，才能评价业务效果。

## 保存与恢复

顶部书签保存当前对象、对象集、视图及时间。保存记录可再次打开；复制链接用于在本机原型中恢复相同工作位置。跨模块返回保持原探索范围，报告正文中本次分析的对象范围与返回后的探索范围可以不同。
