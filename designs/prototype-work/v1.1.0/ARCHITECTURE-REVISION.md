# 组合原型结构修订

## 修订原因

原组合候选通过全局场景切换和 iframe 加载各场景原生 Shell，导致：

- 用户需要在场景之间切换；
- 数据工程、本体、报告等页面无法同时看到四场景资源；
- S003/S004 原生 Shell 出现第二层导航；
- 历史运行投影容易被误认为当前组合运行。

## 当前结构

组合工作区现在只保留一套 Shell 和一层模块导航：

```text
统一 Shell
├── 总览：四场景运行卡片与顺序运行
├── 数据工程：S001—S004 数据源、快照、管道、资产版本
├── 本体管理：S001—S004 Published 本体与资源范围
├── 智能问数：S001—S004 Agent、推荐问题与运行状态
├── 决策中心：S001—S004 Action Request、确认与待办摘要
├── Agent 应用：S001—S004 Agent Run/Result/证据
├── 报告中心：S001—S004 报告定义、产物与核验
└── 仪表盘：S001—S004 运行进度和经营摘要
```

场景不再作为产品级切换项；场景身份只出现在表格列、业务记录、运行详情和证据引用中。所有运行操作按单个场景卡产生新 `scenarioRunId`，四场景顺序运行由总览入口编排。

## 边界

- 组合 Shell 不复制模块业务真值；模块聚合页展示的是场景来源的只读摘要；
- 运行状态只写入组合运行命名空间，不覆盖原场景工作区；
- 历史 Action、通知、审批和待办不因组合运行重放；
- S003/S004 的正式资源和 Checkpoint 仍需对应 Owner 维护；
- 组合运行完成不等于模块评审、场景验收或一期验收通过。
