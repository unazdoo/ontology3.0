# 智财问策 Palantir 范式优化与重构建议

## 1. 结论先行

本轮建议不是把智财问策做成 Palantir 的界面复刻，而是吸收其更成熟的产品组织方式：

1. 首页恢复右侧功能入口区，左侧保留三域架构图。点击三个能力域时，只切换选中态和右侧入口内容，不移动架构、不重排页面。
2. 平台从“按模块解释功能”转为“按业务对象、业务目标和用户任务进入工作”。M01—M08 仍作为稳定能力模块存在，但不要求用户先理解模块编号。
3. 多视图探索建议重构为“业务对象探索”，形成对象发现、对象全貌、关系分析、时序分析、地图和对比分析共用同一上下文的工作台。
4. 模型优化中心建议重构为“模型目标与优化”，先选择业务目标，再进入模型、评测、候选观察、发布消费和代码仓，而不是先面对一条复杂生命周期。
5. 建立跨模块共享的 `工作上下文`：对象集、当前对象、时间范围、对比基准、结果身份和证据范围。问数、探索、模型、Dashboard、报告和决策围绕同一上下文协作。
6. 一期只做直接提升用户价值的高保真闭环，不新增安全、权限、审批、运维、生产部署等门禁型页面，不建设第二套 Shell，不扩展低价值配置项。

## 2. 参考资料带来的核心判断

### 2.1 Palantir 的真正优势不是模块多，而是复用边界清晰

本地 Foundry 演示资料把平台归纳为三个持续循环的能力域：

- Data & Ontology：连接、加工、质量、对象和关系。
- Digital Twin & Modeling：对象分析、模型目标、模拟和优化。
- Operations & Actions：态势、告警、业务应用和行动。

中间的 Foundry OS 不是第四个功能目录，而是让三个能力域共享对象、状态和运行基础。对智财问策的启发是：模块应继续存在，但用户入口应围绕“我要分析什么、优化什么、处理什么”。

### 2.2 Ontology 是业务对象与应用的共同语言

官方 Ontology 文档把 Ontology 定义为组织的 operational layer，包含对象、属性、关系等语义元素，也包含动作和函数等动态元素。Object Explorer、Insight、Quiver、Workshop 等应用都消费同一 Ontology。

智财问策应进一步把以下资源连成一个稳定对象体系：

`数据源 -> 数据快照 -> 数据资产 -> 对象类型 -> 业务对象 -> 对象集 -> 探索 -> 模型目标 -> 模型结果 -> 决策事项 / 报告`

### 2.3 发现、分析、时序和业务应用应分层，而不是塞进一个页面

- Object Explorer 适合不知道有哪些数据的用户，用于搜索对象、筛选对象集和打开对象详情。
- Insight 适合已经知道分析方向的用户，用分析路径串联过滤、关系穿透、聚合、集合运算和可视化。
- Quiver 适合对象与时序数据的深入分析，支持画布、依赖图、参数化和多图联动。
- Workshop 强调对象数据、统一设计和应用状态，让表格、筛选、详情、图表与操作围绕同一对象集联动。

因此，当前 M07 不应继续只是“对象目录加五个 Lens”，而应形成从简单发现到复杂分析的渐进式体验。

### 2.4 模型应按业务目标管理，而不是按算法或流程步骤管理

官方 Modeling Objectives 将其定义为一个具体建模问题的 mission control，用于集中模型、数据、评测、审查、发布、部署和反馈。模型可以来自代码仓、外部环境、API、模拟或优化程序，但进入平台后都围绕同一个 Objective 被比较和消费。

当前 M08 已经具备目标、模型、Benchmark、候选、Shadow、Release 和 Binding，但页面组织仍偏“生命周期说明”。下一步应把“业务目标”提升为页面主对象，把生命周期变成目标详情中的状态与操作。

### 2.5 AI 应嵌入业务应用状态，而不是成为独立聊天孤岛

本地 Ontology-Driven Agents 资料展示了 Application State：当前对象、对象集、引用和页面选择直接成为 Agent 上下文，结构化输出再驱动页面状态。对智财问策的启发是：M03、M05 不应只做对话或 Agent 目录，而应读取用户正在查看的对象、时间和结果视图。

## 3. 目标产品架构

### 3.1 用户看到的三层架构

建议首页三域调整为更直观的业务语言：

| 能力域 | 回答的问题 | 对应模块 |
| --- | --- | --- |
| 数据与本体 | 数据从哪里来，如何变成可信业务对象？ | M02、M01 |
| 探索与建模 | 发生了什么、为什么、未来可能怎样？ | M07、M03、M08 |
| 运营与智能 | 当前需要关注什么，怎样协作与交付？ | Dashboard、M04、M05、M06 |

中心仍保留“智财问策”，表达三域共享一套对象、状态和运行基础。

### 3.2 平台级共享对象

建议将以下资源作为所有模块都能引用的通用合同：

| 资源 | 作用 |
| --- | --- |
| DataSource / Snapshot | 表达统一数据源及不同观察时点快照。 |
| DataProduct / DataVersion | 表达可供对象、分析和模型消费的数据资产。 |
| ObjectType / Object / ObjectSet | 表达业务世界、当前对象与分析范围。 |
| Exploration | 保存筛选、关系穿透、时间范围、可视化和结论。 |
| ModelingObjective | 表达一个稳定业务问题及其输入输出合同。 |
| ModelVersion / EvaluationRun | 表达模型实现、版本和同口径评测。 |
| ResultPackage | 表达正式、候选、影子、模拟和差异结果。 |
| DecisionItem / Report | 表达结果进入协作和交付后的业务产物。 |

### 3.3 共享工作上下文

所有分析型页面共享一个紧凑的上下文对象：

```text
WorkspaceContext
├─ objectSetRef       当前对象范围
├─ activeObjectRef    当前选中对象
├─ timeRange          当前时间范围
├─ comparisonRef      同行、历史或候选对比基准
├─ resultView         正式 / 候选 / 影子 / 模拟 / 差异
├─ dataVersionRef     当前数据版本
├─ ontologyVersionRef 当前语义版本
└─ evidenceRefs       当前证据范围
```

页面顶部只显示业务可理解的上下文摘要，例如“21 家企业 · 2025-12-31 · 正式结果”，技术 ID 放在展开区。用户从 M07 进入 M03、M08、Dashboard 或 M06，再返回时应恢复同一上下文。

## 4. 首页重构建议

### 4.1 推荐布局

```text
┌─────────────────────────────────────────────────────────────┐
│  数据驱动的经营分析与决策                                  │
│                                                             │
│  ┌──────────────────────────┐  ┌─────────────────────────┐ │
│  │                          │  │ 当前能力域              │ │
│  │      三域架构图          │  │ 标题 + 一句业务价值     │ │
│  │  固定几何、单点高亮      │  │                         │ │
│  │                          │  │ 功能入口 1          →   │ │
│  │       智财问策           │  │ 功能入口 2          →   │ │
│  │                          │  │ 功能入口 3          →   │ │
│  │                          │  │ 功能入口 4          →   │ │
│  └──────────────────────────┘  └─────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

右侧不是说明卡，而是真实功能入口列表。每项由图标、功能名称、结果导向短句和进入箭头组成，点击直接打开对应模块任务。

### 4.2 三域入口内容

**数据与本体**

- 数据源：查看来源、快照和最新数据。
- 数据管道：构建、运行和查看历史。
- 数据资产：查找可复用数据产品与版本。
- 本体建模：维护对象、关系、指标和业务定义。
- 语义资产：查看已发布对象模型及下游使用。

**探索与建模**

- 业务对象探索：搜索对象、关系、时序和地图。
- 智能问数：围绕业务问题获得答案和证据。
- 模型目标与优化：比较模型、形成候选并持续观察。
- 模拟与差异：查看压力模拟和正式/候选差异。

**运营与智能**

- 经营驾驶舱：查看整体态势和重点对象。
- 决策工作台：处理需要人工判断的事项。
- 决策运营：跟踪事项接收、判断、分办和完成。
- Agent 应用：运行解释、分析和辅助任务。
- 报告中心：形成可追溯的业务交付物。

### 4.3 动效规则

- 三个圆和中心图形位置始终固定，不做旋转、缩放或重新排版。
- 选中圆使用蓝色实心与路径高亮；其他节点保持黑白线框。
- 右侧入口内容采用 180—220ms 淡入和 6px 位移，容器高度固定，避免页面抖动。
- 功能入口 hover 只改变底色、箭头和左侧强调线，不使用装饰性渐变或悬浮大卡片。
- 移动端不缩小整张架构图：上方显示简化三域图，下方纵向展示当前域入口。

## 5. M07 重构：从“多视图探索”到“业务对象探索”

### 5.1 建议定位

推荐名称：**业务对象探索**。

核心任务不是“切换五种视图”，而是：

> 从一个对象或对象集出发，持续缩小问题范围，穿透关系、时间和空间，形成可保存、可比较、可继续问数或建模的探索结果。

### 5.2 两级体验

**第一级：对象发现**

- 一个主搜索框，同时搜索对象名称、类型和关键属性。
- 对象类型目录按业务含义分组，不按 S001—S005 分组。
- 支持最近查看、已保存探索和常用对象集。
- 搜索结果默认表格/列表，直接展示关键属性、质量和关系数量。
- 点击对象进入对象全貌；选择多个对象进入对象集分析。

**第二级：探索工作台**

```text
┌──────────────┬──────────────────────────┬──────────────────┐
│ 分析路径     │ 主画布                   │ 对象与证据       │
│ 起始对象集   │ 表格 / 关系 / 时序       │ 当前对象         │
│ 筛选条件     │ 地图 / 对比              │ 关键属性         │
│ 关系穿透     │                          │ 关系与事件       │
│ 聚合与比较   │ 所有 Lens 共用同一上下文 │ 数据与版本       │
└──────────────┴──────────────────────────┴──────────────────┘
```

默认用户只看到搜索、筛选和主画布；点击“分析路径”后再展开高级步骤，避免一开始暴露复杂分析结构。

### 5.3 Lens 设计

| Lens | 用户任务 | 关键交互 |
| --- | --- | --- |
| 结果表 | 扫描、排序、筛选对象集 | 列配置、快速筛选、选中对象。 |
| 对象全貌 | 理解单个对象 | 指标、属性、关系、事件、证据。 |
| 关系网络 | 查找关联影响和传播路径 | 逐层展开、路径高亮、按关系类型过滤。 |
| 时序分析 | 查看变化、异常和事件 | 时间刷选、多序列联动、事件标记、同比/环比。 |
| 地图 | 查看空间分布 | 图层、区域筛选、对象聚合和时间联动。 |
| 对比分析 | 比较对象集、历史或同行 | 并列指标、分布、排名和差异解释。 |

Lens 切换只改变主画布，不重建对象目录、筛选条件和时间范围。

### 5.4 跨模块入口

上下文工具栏只保留高价值命令：

- 就此提问：带当前对象集进入 M03。
- 解释当前结果：带对象和结果身份进入 M05。
- 打开模型目标：带对象类型和数据版本进入 M08。
- 加入报告：把当前图表、对象集和证据加入 M06 草稿。
- 查看驾驶舱：跳转到 Dashboard 对应业务视图。

### 5.5 炫酷感应来自数据交互，不来自装饰

- 图谱节点展开时使用路径生长和邻居渐入。
- 时间刷选同步驱动图表、事件列表和关系状态变化。
- 表格选中对象时，关系图、地图和右侧详情同步高亮。
- 对比模式切换时用图形形态过渡，而不是简单替换静态图。
- 所有动画必须保持布局稳定，并支持快速连续操作。

## 6. M08 重构：从“模型流程中心”到“模型目标与优化”

### 6.1 建议定位

推荐名称：**模型目标与优化**。

首要对象是“业务目标”，不是模型算法，也不是生命周期阶段。

### 6.2 一级页面：目标目录

目标目录同时展示所有业务目标，每个目标只回答六个问题：

- 要解决什么业务问题？
- 输入是什么对象和数据？
- 输出是什么结果？
- 当前正式模型是什么？
- 最近一次评测怎样？
- 下一步要做什么？

建议使用紧凑列表或两列卡片，不在首屏展示技术 ID、模型参数和完整流程说明。

### 6.3 二级页面：目标工作台

```text
┌────────────────────────────────────────────────────────────┐
│ 目标：企业债务风险智能监测     当前正式模型 / 最新候选     │
│ 输入对象 · 输出结果 · 数据截至 · 下一步主操作              │
├──────────────┬─────────────────────────────────────────────┤
│ 概览         │ 目标当前态势、最新评测、问题和下一步        │
│ 模型与代码   │ 正式 / Challenger / 补充模型                │
│ 评测对比     │ 同口径比较、切片、漂移、缺失原因            │
│ 候选观察     │ AI 洞察、候选版本、Shadow 时间窗口          │
│ 发布与消费   │ Release、结果绑定、消费者和历史             │
└──────────────┴─────────────────────────────────────────────┘
```

五个页面应始终围绕当前目标，不再在每页重复展示全部五个业务目标。

### 6.4 模型组织

模型按角色分组，而不是混成一个排行榜：

- 当前正式模型：一个稳定对照，保留历史结果。
- Challenger：回答相同问题，可进行同口径比较。
- 补充模型：分别回答时间、事件、流动性、关系、异常和优先级问题。

补充模型不参与“谁是冠军”的总榜，只展示各自业务目标、覆盖率、置信度和使用位置。

### 6.5 评测对比

评测页面采用“比较矩阵 + 证据下钻”：

- 顶部固定评测数据、时间、对象范围和口径。
- 中部并列正式模型与 Challenger 的核心指标。
- 下部展示最差业务切片、漂移、校准、覆盖率和缺失原因。
- 点击任一指标，右侧抽屉展示对象明细、错误样本和证据。
- 支持固定两个版本进行 A/B 对比，不默认展示所有模型。

### 6.6 AI 优化洞察

AI 洞察应附着在具体问题上，例如：

- 哪个指标下降？
- 哪个业务切片表现最差？
- 哪类数据缺失造成不可评价？
- 建议修改哪个特征、参数或校准步骤？
- 若采纳，将创建哪个候选 Model Version？

主操作为“基于建议创建候选分支”，随后进入新的不可变候选版本。AI 洞察不是独立聊天页，也不是自动发布工具。

### 6.7 模型代码仓

代码仓保留 Python IDE 形态，但作为模型详情的专业下钻，不占用一级导航：

- 左：模型仓与文件树。
- 中：README / Python / model-card 编辑器。
- 右：分支、提交、标签、候选版本和运行输入。
- 下：测试与模型运行控制台。

正式模型仓只读，候选模型可从新分支维护；页面主标题始终显示业务模型名称，技术 ID 放在次级位置。

### 6.8 发布与消费

不要只展示 Binding ID，改为可理解的消费者地图：

```text
当前候选版本
├─ Dashboard：候选试算 / 差异
├─ M07：对象与关系探索
├─ M03：问数与横向比较
├─ M05：结果解释
└─ M06：报告与版本比较
```

压力模拟作为独立使用模式，从目标工作台直接启动，不混入候选发布步骤。

## 7. 其他模块的主要优化建议

| 模块 | 主要优化 | 一期不做 |
| --- | --- | --- |
| M02 数据工程 | 形成“数据源 / 管道 / 数据资产”三层；数据源详情以快照时间轴为核心；管道详情统一画布、预览、运行和版本；提供下游影响入口。 | 不增加复杂调度、环境和运维控制台。 |
| M01 本体管理 | 首页改为对象类型和关系地图；对象类型详情集中属性、关系、指标、示例对象和下游使用；草稿与已发布版本切换保持简单。 | 不增加权限矩阵和复杂治理审批。 |
| M03 智能问数 | 保留当前对话、推荐问题和五步动画；增加当前对象/对象集上下文条；引用可点击并跳到 M07 或证据；答案可加入报告或进入决策。 | 不增加复杂 Prompt、模型和检索配置页。 |
| M04 决策中心 | 保留决策运营驾驶舱和工作台；事项详情形成“问题、影响、证据、建议、当前进展”决策包；从 Dashboard/M03 进入时自动定位事项。 | 不增加多层审批配置和流程设计器。 |
| M05 Agent 应用 | Agent 按任务结果分类，如解释、比较、报告辅助；打开 Agent 后直接读取当前对象和页面状态；目录、运行和结果三层即可。 | 不增加 Agent 框架、工具协议和权限配置中心。 |
| M06 报告中心 | 报告由对象集、指标、图表、问数答案和证据块组成；支持从 M03/M07/Dashboard 一键加入草稿；保留历史版本比较。 | 不做复杂排版设计器和出版系统。 |
| Dashboard | 定位为 Control Tower：整体态势、重点对象、时间窗口、影响、待处理事项和结果模式；模型只作为结果来源，不形成模型目录。 | 不重复建设 M07 分析器或 M08 模型后台。 |

## 8. 推荐实施优先级

### P0：直接改变整体体验

1. 首页恢复 Palantir 式右侧功能入口区。
2. 建立跨模块 `WorkspaceContext` 和返回上下文。
3. M07 重构为对象发现 + 探索工作台。
4. M08 重构为目标目录 + 目标工作台。

### P1：强化端到端价值

5. M02 统一数据源快照、管道版本和数据资产的层级。
6. M01 增加对象关系地图和下游使用视图。
7. M03、M04、M06 跑通“答案/探索 -> 决策/报告”的直接交接。
8. Dashboard 与 M07 共享对象集、时间范围和结果模式。

### P2：专业化与视觉提升

9. M05 改为任务型 Agent 目录与嵌入式运行体验。

## 9. 一期明确不做

- 不新增安全中心、权限中心、审批配置、治理门禁等页面。
- 不建设生产部署、资源调度、容器、监控告警和多环境发布后台。
- 不把所有 Palantir 功能映射为菜单项。
- 不再增加场景选择器、说明性流程卡和技术概念墙。
- 不复制同一对象、模型或结果到多个模块形成不同口径。
- 不为了“炫酷”增加与数据状态无关的动画、渐变和装饰组件。

## 10. 重构验收标准

1. 用户进入首页后 5 秒内能判断三个能力域，并一键进入目标功能。
2. 首页切换能力域时架构图不移动、页面不抖动、内容不重载。
3. M07 用户可从搜索对象开始，在同一上下文完成筛选、关系、时序、地图和对比。
4. M08 用户可先理解业务目标，再查看模型、比较评测、形成候选、观察表现和查看消费者。
5. 任一页面只有一个明确主操作，技术身份与证据按需展开。
6. M03、M07、M08、Dashboard、M06 之间切换时对象、时间和结果模式保持一致。
7. 移动端重组为纵向任务流，不缩小桌面表格和三栏工作台。
8. 所有入口、切换、保存、运行、比较和返回均为真实交互，不使用静态成功状态。
9. 1440×900、1280×720、390×844 无页面横向溢出，控制台与资源错误为 0。

## 11. 建议下一步原型范围

下一轮只建议先建设四个高价值页面并完成评审：

1. 首页三域架构 + 右侧功能入口。
2. M07 对象发现页。
3. M07 探索工作台。
4. M08 目标目录与一个完整目标工作台。

四个页面确认后，再把同一 `WorkspaceContext` 接入 M03、Dashboard、M04 和 M06。这样可以先确定平台最关键的对象和目标交互范式，避免再次在全部页面上重复返工。
