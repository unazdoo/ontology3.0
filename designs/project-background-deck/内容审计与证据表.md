# ontology3.0 项目介绍：旧稿审计与证据表

核验日期：2026-08-12  
修改边界：本文件及后续 HTML 仅位于 `designs/project-background-deck/`；`deliverables/`、其余 `designs/` 原型和 `outputs/` 原始工作簿均只读。

## 1. 旧稿问题审计

### 1.1 证据链

- `方案A-数智中枢.html`、`方案B-经营价值.html`、`方案C-决策旅程.html` 各有 8 张样页，但均没有可核验的页脚来源。
- 旧稿中的 5,218、574、24 没有给出文件、工作表、计算口径或数据截至时间，不能直接沿用；本轮已从原工作簿重新计算。
- 旧稿关于“看板止步于看见”“更新后没人敢确定信哪版”“关键知识依赖少数专家”等判断，没有项目流程、工作簿结构或权威公开资料支撑，不进入新主讲页。

### 1.2 叙事与文案

- `index.html` 同时提出 A/B/C 三套各 32 页标题序列，超出 20 分钟、18–22 页主讲范围，并让评审先选择讲法而不是理解项目事实。
- 标题语法混用口号、问题句、模块名和结论句；只读标题无法稳定复述项目主线。
- 明确删除或改写：`让可信数据走向可执行决策`、`本体把业务世界变成共同语言`、`从看板到行动的关键断点`、`让每一个数字可追溯，让每一个建议可落地`、`财务 AI 的可信经营闭环`。
- 删除同类绝对化表达：`权威事实只维护一次`、`每一层都有唯一责任与证据`、`每一个行动都有负责人、状态与结果`。数据、语义、报告和运行事实有不同 Owner 与版本，不能合并成一个“唯一事实”。
- 删除英文眉题堆叠：`THE BROKEN HANDOFF`、`ONE TRUSTED CHAIN`、`HUMAN-IN-THE-LOOP` 等不再作为中文事实标题的竞争层级。

### 1.3 信息结构

- 旧稿没有先说明当前可核验数据集的性质、规模、字段结构和业务截至时间缺口。
- C 页 4 把业务对象与 Metric/Rule 画成同类节点，混淆 Object 与语义资源。
- C 页 7 的 S001 轨道跳过 Action Request；旧图还把“银行协商建议/待办”写成已发生的协商结果。
- 旧稿没有清楚区分：数据资产版本、Published 语义版本、报告内容/证据版本、Action Request/提醒/待办运行状态。
- S003 的文字容易被读成兼容性已通过或场景已建成；新稿固定写为“数据内容已确认、待受控发布验证；完整场景尚未启动”。

### 1.4 视觉与投影

- A 含 21 处线性渐变、6 处径向渐变、20 处阴影和 4 处 `backdrop-filter`；B 使用米色纸张、铜色、渐变和重阴影；C 仍大量使用渐变、阴影和 9–14px 圆角。
- 三套方案都依赖柔软卡片和装饰光效，与本轮的灰白系统画布、近黑框架、0–4px 圆角、1px 结构线不一致。
- C 的关系注释 18px、架构标签 21–22px；B 的团队信息 21–23px。它们属于正文而不是来源，低于本轮正文 24–30px 要求。
- 页面上的“返回”“三方案评审入口”“推荐现场展示”“本轮”“样页”等制作过程文案不进入正式页面。

### 1.5 可保留的事实与图形类型

- 团队姓名、部门和现稿中列明的正式分工；正式扩展前仍建议由团队复核一次。
- 六模块边界：Metric、Rule、Action Type 定义归本体管理；Action Request 进入决策中心；人工确认后才创建负责人待办；通用仪表盘和管理驾驶舱归报告中心；LLM 只解释固定证据。
- 数据工程流程顺序：来源登记、原始快照、受控处理、质量检查、数据资产版本、提交本体刷新请求并读取结果。
- 对象关系图、模块架构、流程轨道三种图形类型，但全部按统一的线性几何语法重画。

## 2. 不进入主讲页的结论

- 集团真实融资规模、真实业务数据截至时间、真实融资节约金额或效率提升。
- 原始来源载体数量、融资数据历史版本数量、人工处理耗时。
- “行业普遍存在”“大量看板无法行动”“个人助手造成组织知识分散”等未提供证据的泛化判断。
- S002、S003、S004 的未确认指标、规则、风险评分、预算结论或报告正文。
- 将当前脱敏生成数据集中的金额、机构名称和主体名称解释为生产经营事实。
