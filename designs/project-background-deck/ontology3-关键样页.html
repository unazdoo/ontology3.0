02 · 三项平台边界

本项目用三条边界控制数据、语义和执行

已确认合同
01 / VERSION

版本边界

数据资产版本与 Published 语义版本分别发布，再由权威消费绑定固定精确组合。

不把“刚到达”“已发布”“可消费”和“当前权威”写成同一种状态。
02 / SEMANTICS

语义边界

Metric、Rule、Action Type 的定义、依赖和 Published 生命周期归本体管理。

LLM 解释固定结果，不作为数据源、正式计算层或 Rule 引擎。
03 / ACTION

执行边界

Rule、问数、Agent 和仪表盘只提交 Action Request，后续运行归决策中心。

未经人工确认不得创建负责人待办；确认与待办创建分别留痕。
共同约束不同版本不混用模型不补数或改口径未确认不创建待办
来源：平台总控台账 C003、C005–C013、C019；本体管理 §1.2；智能问数 §3.6；决策中心 §3、§5–6。 02 / 10

05 · 业务口径

平均融资成本必须按余额加权，简单平均会改变结果

可复算口径
按余额加权Σ（融资明细人民币余额 × 当前利率）
÷ Σ 融资明细人民币余额2.849%
单位成本简单平均（脱敏主体 553 单位成本 + 脱敏主体 561 单位成本）
÷ 22.555%
同一两主体组合采用两种口径，复算结果相差 0.295 个百分点。差 0.295 个百分点

Metric 合同固定什么

对象范围明确主体集合和去重规则。
公式在融资明细并集上按人民币余额加权。
单位与时间固定百分比口径、数据时点和评估时间。
异常处理区分零余额、缺失、重复和不可计算。

直接影响：单位与组合比较、Rule 评估和问数回答必须引用同一 Published Metric 定义。
