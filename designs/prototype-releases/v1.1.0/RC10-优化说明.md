# v1.1.0-rc.10 产品优化说明

当前状态为“已完成组装、待用户走查”，`acceptanceReady=false`。

## 首页架构

- 三条能力路径始终分别显示箭头。
- 非当前路径使用清晰中性色箭头；当前路径使用蓝色箭头和沿线信号。
- 三能力域切换仍只驱动自身路径，不旋转或误亮其他路径。

## 报告问答

- 报告助手默认宽度由 370px 提升为 440px，可拖拽范围为 390—620px。
- 1440 宽度下正文约 755px、助手 440px；1280 宽度下助手保持 440px。
- 推荐问题改为单行横向 chips，不再占据大面积垂直空间。
- 回答区域使用主要可用高度和宽度，保留结论、关键依据、证据状态、需要关注及使用边界。
- 问答过程使用低频神经节点、三阶段状态和进度光带，原位更新，不重建正文 iframe。

## 自动核验模型

自动核验采用三层结构：

1. `1 个 Agent 抽取批次`：独立“报告自动核验 Agent”从固定报告内容抽取结构化声明，定位稳定锚点和证据引用；
2. `5 个规则组`：报告身份、定义模板、语义数据、内容事实、人工复核与产物五类确定性核验分类；
3. `N 个核验项`：规则组中的逐条声明—证据比对单元，例如 S004 为 18 个核验项。

Agent 抽取不是第六个规则组。它只形成 `claims`、`anchors`、`evidenceRefs` 和 `comparisonRequests`，比较请求固定为 `not-evaluated`；正式通过、警告或失败由报告中心确定性规则引擎判定。

## Agent 边界

- 报告伴读 Agent 只负责报告问答。
- 报告自动核验 Agent 使用独立配置 `report-verification-agent@1.0`。
- 核验 Agent 的 Prompt、Skill、Tool 和运行结果均在 Agent 应用中可查看。
- 核验 Agent 不读取业务明细、不重算指标、不替代数据工程质量判断，也不发布报告。

## 过程动效

- 自动核验按“锁定上下文、抽取声明、定位锚点、确定性判定、固定记录”五阶段推进。
- 页面显示已抽取、已定位和已判定数量，以及当前阶段信号轨道。
- 动效使用克制的信号移动和节点脉冲，不闪烁、不改变布局；`prefers-reduced-motion` 下停用。

## 验证边界

普通 Chrome 对组合入口加载和刷新均无控制台错误。Codex 内置浏览器的 `MutationObserver.observe` 日志来自其页面注入层，应用已移除全局错误屏蔽，不隐藏真实产品错误。

本轮内部检查不表示模块正式评审通过、场景正式验收通过或一期验收通过。用户明确通过前不冻结为正式基线。
