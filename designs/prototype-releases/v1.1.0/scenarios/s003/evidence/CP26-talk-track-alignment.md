## 讲解稿与当前实现的收敛

讲解稿中的“黑灯、红灯、黄灯预警将直接推送至决策中心”和“相关决策人确认并提交审批”是业务层概括。按照已确认的一期平台合同，当前实现采用以下精确语义：

1. 评分完成后，系统按风险分档亮灯自动形成预警入口；黄灯、红灯、黑灯均纳入行动候选，绿灯不形成行动。
2. 集团债务风险管理人员在 M06 驾驶舱查看企业报告后，显式提交标准 C011 Action Request。
3. 提交阶段只建立行动申请并按企业稳定路由送达对应成员单位债务风险接口人的通用决策中心；不预置负责人，不创建待办，不向集团管理员统一收件。
4. 成员单位接口人核实事实、确认行动申请并选择本单位负责人后，才形成负责人待办；一期不建设集团统一审批、多级审批或独立处置页面。
5. 重大诉讼、资金余缺等调节因子只作为诊断证据和行动说明，不单独制造第二条行动。

## 浏览器诊断说明

应用源码和实际加载资源中没有业务 `MutationObserver` 调用。当前 in-app Browser 诊断日志中的 `Failed to execute 'observe' ... parameter 1 is not of type 'Node'` 来自浏览器自动化注入层的全局监听初始化（其注入脚本包含对 `this.document` 的 `MutationObserver.observe`），在不同端口和干净标签页均可复现；页面功能和应用侧资源加载不受影响。该工具层噪声不作为 S003 业务错误计入，但保留在 CP26 证据中，`acceptanceReady` 继续为 `false`，待用户验收时可用独立真实浏览器/自动化运行器复核。
