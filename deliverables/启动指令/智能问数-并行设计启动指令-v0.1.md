四、一期核心目标

用一个演示账号基于 Published 本体和当前获准数据版本完成真实问数，而不是直接把工作簿或整表塞给 LLM。

S001 必须覆盖：
1. 查询单家单位平均融资成本及构成。
2. 查询任意两家单位综合平均融资成本。
3. 查询三家单位综合平均融资成本。
4. 查询集团融资成本、债务结构和产业板块对比。
5. 解释三条 Rule 分别为何命中三家不同单位。
6. 根据异常贷款和成本贡献指出优先协商的金融机构，并给出可追溯证据。
7. 从回答中发起受控 Action 请求；提醒、人工确认和待办由决策中心承接。
8. 每次回答显示 Published 语义版本、可消费数据版本、数据截至时间、生成时间和证据引用。

五、本模块必须详细设计

1. 智能问数定位、用户、一期/后期边界和成功判据。
2. 问数 Agent 的系统提示词、Skill、本体绑定、资源白名单和配置版本；只负责问数 Agent，不包含报告/洞察 Agent。
3. 问题输入、范围确认、歧义澄清、语义解析、查询计划可解释性、回答和追问。
4. 对象、Metric、Rule、关系和 Action Type 的发现与引用方式。
5. 多单位组合、筛选、时间范围、集团/板块/单位层级和金融机构归因。
6. 证据展示、版本证明、数据新鲜度、质量警告和不可回答边界。
7. 常用问题、历史会话、可复用问数视图，以及固定到仪表盘的跨模块输出合同。
8. Action 请求的发起入口、确认前提示和提交结果；不得设计决策中心内部状态机。
9. 加载、空、无匹配、口径冲突、数据陈旧、刷新中、质量失败、本体不兼容、LLM 失败和重试恢复。
10. 页面/工作区、功能能力地图、关键旅程、状态、交互合同和业务可执行验收。

1. 不配置数据采集、管道、Python 处理或数据资产发布。
2. 不创建或修改 Object、Metric、Rule、Action Type。
3. 不拥有报告/洞察 Agent、报告定义或正式报告。
4. 不拥有提醒、人工确认和负责人待办的运行记录。
5. LLM 不作为数据源或正式 Metric/Rule 计算层；只基于受控语义查询结果组织解释。
6. S002—S004 在一期最终必须完整实现，但在用户补充资料前只说明扩展机制，不虚构问题集、口径或回答。
