五、本模块必须详细设计

1. 产品定位、一期/后期边界、用户和成功结果。
2. Action 请求、决策提醒、人工确认、负责人待办及其业务关系。
3. 提醒来源：Rule 命中、智能问数、Agent 应用和仪表盘受控入口。
4. 决策工作台、提醒详情、证据查看、确认/拒绝、待办目录、待办详情和追溯入口。
5. 每条提醒必须显示对象主体、Rule/Action Type 引用、Metric 快照、语义/数据版本、数据截至时间、来源和生成时间。
6. 人工确认前的校验、确认理由、负责人、到期时间和可修改项；默认期限仍按 Q003 状态处理。
7. 待办创建、状态更新、完成、取消、逾期、失败和纠正，但一期单账号不设计角色切换或审批链。
8. 重复请求、同一主体多次命中、跨主体同负责人、数据版本变化、证据陈旧和上游撤回的处理。
9. 加载、空、失败、部分可用、版本不兼容、证据缺失、提交失败和重试恢复。
10. 页面/工作区功能合同、能力地图、关键旅程、生命周期、状态矩阵和业务可执行验收。
11. 向报告中心提供只读决策运行摘要；报告中心不得维护另一套状态。

六、明确边界

1. 不定义 Metric 公式、Rule 阈值或 Action Type 业务合同。
2. 不配置数据管道、数据质量或数据资产。
3. 不设计智能问数如何理解问题或 Agent 如何生成分析。
4. 不拥有仪表盘、报告定义或报告产物。
5. 不允许仪表盘、智能问数或 Agent 绕过人工确认直接创建负责人待办。
6. S002—S004 一期最终必须完整实现，但用户未补充资料前不得虚构其决策规则、提醒或待办流程。
