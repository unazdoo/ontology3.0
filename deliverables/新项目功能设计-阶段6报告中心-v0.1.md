### 0.2 一页结论

1. `[已裁决][D035][D041]` 报告中心是平台的**持续经营观察与正式报告产物中心**，负责回答“发生了什么、经营情况怎样”；拥有通用业务分析仪表盘、管理驾驶舱、指标趋势、单位对比、专题分析和报告展示能力。
2. `[已裁决][D019]` 一期仪表盘按场景代码定制，不建设组件市场、用户拖拽、自由布局或配置化搭建器。仪表盘版本代表界面结构和资源绑定的发布版本，不因业务数据变化自动生成新界面版本。
3. `[已裁决][D036][D039][D040][D041]` 决策中心负责回答“需要决定什么、由谁执行、执行到哪一步”，并且是提醒、人工确认、负责人待办和执行状态的唯一运行事实来源；报告中心不得拥有“决策运营概览”或复制决策流程。
4. `[已裁决][D037][D038]` 报告中心仪表盘可以提供“发起行动”入口，但只能向决策中心提交引用已发布 Action Type 的标准 Action Request；不得直接创建负责人待办，不得执行确认/拒绝或更新待办状态。
5. `[跨模块待定][RC-X-001]` D035 已确认仪表盘定义和版本归报告中心；Q018 目前仅剩平台是否设置独立一级“仪表盘”消费入口待裁决，不影响报告中心 Owner 和 C016 已确认边界。
6. `[跨模块待定][RC-X-002]` 在 Q019 裁决前，暂按“业务对象、Metric、Rule 和关系经 Published 本体及权威消费绑定消费；数据工程只直供可信度元数据摘要”设计，报告中心不得从工作簿、原始快照或资产字段重算业务指标。
7. `[已裁决][D020][D024]` 一期最终必须完整实现 S001—S004 四个入口。当前只完整设计 S001；S002—S004 当前状态均为“资料待补充”，不是“已完成”或“可验收”。
8. `[已裁决][D021]` 确定性指标和 Rule 结果来自 Published 本体；LLM 只基于固定证据包生成 AI 洞察或报告草稿，不作为数据源或正式计算层。
9. `[已裁决][D022]` 报告中心拥有报告定义、报告模板、报告草稿复核副本、复核结论和正式报告产物；Agent 应用拥有报告/洞察 Agent 配置、提示词、Skill、工具白名单和运行记录。
10. `[已裁决][D023]` 场景编号、入口和跨模块资源引用由平台公共场景清单维护；报告中心引用 S001—S004，不复制六模块资源定义或运行状态。
11. `[已裁决][D044][D046][D050][RC-DE-006][RC-DE-011]` 正式报告在生成时固定精确语义/数据证据和版本绑定摘要，旧 HTML/PDF 不随后续刷新原地改变；数据工程按 C017/C030 只读提供生成时摘要、核验时摘要、五维状态和保留/恢复状态。`[待用户裁决][Q025]` 只决定一期是否真实执行历史数据侧重放，不阻断固定报告证据核对。
12. `[本模块设计][一期最小实现][已裁决][D042][RC-X-009]` Report Copilot 按单一 Owner 拆责：报告中心拥有侧边页签、报告/章节/锚点的选择意图、确定性核验及四态、复核问题和重新生成入口；Agent 应用拥有正式 Context Binding、会话、运行、问答和核验解释结果。C014、C024、C025 已生效，双方只保存对方标识并回读权威状态。
13. `[已裁决][D043][D047][RC-X-010]` 报告证据事实根固定为“报告/草稿精确版本 + 稳定锚点 + 证据包”，追溯 Object Type、Object 实例/集合、Property、Link、Metric、Rule 和必要 Action Type 的稳定标识与生成时精确 Published 版本；C022、C024、C026 已生效，不得用名称、当前 Published 或当前/上一 T019 替代历史引用。
14. `[已裁决][D044][D045][D047][RC-DE-011][RC-DE-012]` 历史核验按报告冻结证据、版本定位、内容访问、证据完整、重放能力、重放核验和端到端同口径结论分层；当前比较按报告快照、当前 T019、候选和两类上一可信证据分列。报告中心分别拥有最终确定性四态和 C027 比较记录，Agent 只读解释。
15. `[已裁决][D046][本模块设计][一期最小实现]` 系统内受控 HTML 是一期主要交互式阅读形态，与 PDF 固定版及打印视图共享同一报告编号、内容版本和证据链；已发布 HTML/PDF 均冻结。DOCX 默认列入后期，只有 S004 后续资料明确要求 Word 正式交付时，才在同一主文档中增量纳入一期。
16. `[已裁决][D021][D043][D047][本模块设计][一期最小实现]` 长报告可以由 Skill/Agent 生成，但 Agent 只返回结构化内容项和证据引用；正式 Metric、Rule 和业务计算必须在进入证据包前由 Published 或其他已批准的确定性结果提供。报告中心形成内容项—稳定锚点—证据绑定，执行确定性核验；LLM 核验说明必须使用独立 Agent Run/Result，不能复用生成运行自证或改变四态。
17. `[本模块设计][一期最小实现]` 长报告只建设一套渐进披露体验：整份/章节/锚点范围核验、报告级—章节级—检查类型级汇总、证据覆盖和问题筛选。完整历史重放、大规模恢复、任意全文语义比较和报告内临时业务公式不作为报告中心一期能力。

## 1. 产品定位、用户与范围边界

### 1.1 报告中心定位

`[已裁决][D035][D041]` 报告中心围绕“发生了什么、经营情况怎样”回答两个观察与报告问题：

- **现在发生了什么、经营情况怎样、值得关注什么。** 由仪表盘回答，强调当前范围、确定性事实、可信度、趋势、比较、专题分析、下钻和跨模块入口。
- **基于什么证据形成了哪一版正式结论。** 由报告回答，强调定义、固定证据、草稿复核、发布产物和历史追溯。

`[已裁决][D036][D039][D041]` “需要决定什么、由谁执行、执行到哪一步”由决策中心回答。报告中心不是数据加工工具、本体建模工具、问数 Agent 配置工具、决策工作台、决策运营概览或 Agent 编排平台；它组合并引用权威资源，但不改变其 Owner。报告中心内对报告草稿的复核确认仅属于报告产物流程，不等同于决策中心的人工确认。

## 2. 仪表盘与报告的资源边界

### 2.1 两类资源的不同业务目的

| 维度 | 仪表盘 | 报告 |
|---|---|---|
| 主要问题 | 当前范围内发生了什么、哪里异常、下一步去哪里 | 在固定证据和版本下形成了哪一版可复核、可发布结论 |
| 使用方式 | 持续浏览、筛选、比较、下钻、跳转 | 发起生成、复核、退回、确认、发布、阅读和追溯 |
| 时间特征 | 面向当前兼容事实持续更新 | 面向某次生成时点固定 |
| 内容构成 | 确定性内容、可信度内容、AI 洞察三层分区 | 报告定义、模板骨架、固定证据、Agent 草稿、人工复核、正式产物 |
| 主要阅读形态 | 页面内持续交互视图 | 系统内受控 HTML 为主，PDF 固定版和打印视图同源；草稿与正式产物均可打开报告助手 |
| 版本 | 仪表盘版本描述界面结构和资源绑定 | 报告定义、模板、草稿和产物分别有版本 |
| 对新数据的行为 | `[待数据工程确认][RC-DE-004]` 随当前兼容、消费就绪的数据更新，不生成新仪表盘版本 | `[已收敛][D044][D050][RC-DE-006][RC-DE-011]` 报告中心保证旧产物不原地变化；生成时绑定原精确数据版本/T008/版本绑定摘要，后续访问/重放状态只追加披露 |
| AI 角色 | 作为单独标识的洞察层，可陈旧、可重新生成 | 生成草稿，必须经过人工复核才能成为正式产物 |
| 业务行动 | `[已裁决][D037][D038]` 只提交引用已发布 Action Type 的标准 Action Request，并提供决策中心深链 | 报告正文可引用只读决策证据，但不从报告直接执行 Action、确认或创建待办 |

### 2.2 仪表盘定义、报告定义和报告模板

- **仪表盘定义**说明场景编号、业务目标、固定页面结构、组件与权威资源引用、支持的语义范围、版本和发布状态。一期由产品发布登记形成，不向用户开放配置。
- **报告定义**是可复用业务合同，规定为什么生成、给谁使用、覆盖哪些对象和证据、引用哪个模板、调用哪个 Agent/Skill、如何校验、谁复核、何时可发布。
- **报告模板**只规定章节骨架和版式。替换模板不会自动改变证据范围、指标口径、Agent/Skill 或发布规则；修改这些内容必须修改报告定义。

### 2.3 生命周期必须分开

| 资源 | 生命周期主轴 | 关键规则 |
|---|---|---|
| 仪表盘版本 | 待登记 → 联调中 → 可发布 → 已发布 → 已停用 | 数据变化不改变仪表盘版本；结构、绑定或交互变化才形成新版本 |
| 报告定义版本 | 编辑中 → 校验失败/校验通过 → 已启用 → 已停用 | 已启用版本不可原地改合同；修改后形成新定义版本 |
| 报告模板版本 | 编辑中 → 可引用 → 已停用 | 已生成产物继续保留原模板版本引用 |
| 一次报告生成 | 已提交 → 固定证据中 → 生成中 → 自动核验中/核验阻断 → 草稿待复核 → 退回/已确认 → 发布中 → 已发布 | 证据缺失、生成失败和硬核验阻断为独立状态；退回后可基于原证据重生成或重新固定证据 |
| 正式报告产物 | 待发布 → 已发布 → 已被替代/已撤回 | 已发布内容不可原地修改；替代和撤回保留原产物及原因 |
| 正式报告表现形态 | 随同一产物完成 HTML 阅读版与 PDF 固定版/打印视图的形成、发布、替代和撤回 | 两种形态共享报告编号、内容版本和证据链，不建立两套内容生命周期；任何内容变化必须形成新产物版本 |
| 报告复核问题 | 待处理 → 处理中 → 已解决/已关闭 | 报告中心拥有问题记录；问题必须绑定草稿/产物版本、稳定锚点和证据，不能直接改写已发布内容 |
| AI 洞察展示 | 生成中 → 待确认/可发布 → 已确认展示 → 已陈旧/生成失败 | `[跨模块待定][RC-X-006]` 权威确认状态不在报告中心维护副本 |

### 2.4 平台一级消费入口与报告中心管理入口

`[已裁决][D035]` 仪表盘定义、版本和管理能力已经归报告中心。`[跨模块待定][RC-X-001]` Q018 目前只决定是否设置平台独立一级“仪表盘”消费入口，采用以下候选导航关系：

| 候选入口 | 主要用户任务 | 展示内容 | 与另一入口的关系 |
|---|---|---|---|
| 平台一级“仪表盘” | 直接进入 S001—S004 场景消费 | 场景清单、就绪状态、已发布仪表盘/报告入口 | 读取平台公共场景清单；不承担资源管理 |
| “报告中心”管理入口 | 管理仪表盘版本、报告定义、模板、生成复核和正式产物 | 资源目录、版本、生成工作区、复核队列、正式产物库 | 为平台一级入口提供已发布资源，不复制场景清单 |

推荐该方案的理由：消费路径短，管理职责清楚，同时不新增第七业务模块。若 Q018 不采纳独立一级入口，S001—S004 的消费入口应落在报告中心或平台公共场景导航中；仪表盘 Owner、C016、报告中心管理页和受控 Action 边界均不重新打开。在裁决前，页面编号只表示功能合同，不代表最终主导航位置。

### 3.4 通用导航与上下文

- 从 RC-P0 进入场景后始终保留“场景编号 → 当前范围/对象 → 仪表盘版本”的上下文。
- 从 S001 打开智能问数、决策中心或 Agent 分析后，返回时恢复原范围、筛选、所选单位和滚动位置。
- `[已裁决][D039]` 从决策运行摘要打开决策中心时，跳转目标是决策中心拥有的 Action Request、提醒或待办详情；回链只携带 S001 场景、主体、原筛选和返回位置，不携带任何可回写决策状态的动作。
- 返回 S001 后重新读取决策中心的当前摘要；不得用跳转前缓存覆盖决策中心状态，也不得在报告中心保存一份可编辑的提醒、确认或待办记录。
- 从正式报告产物打开追溯，再返回时恢复产物筛选和原阅读位置。
- RC-P9/RC-P12 的目录、正文、报告助手和证据详情共享当前草稿/产物版本及稳定锚点；从助手结果打开证据再返回时，恢复子页签、核验项、所选锚点和滚动位置。
- 长报告从报告级摘要进入章节级汇总，再进入锚点级问题；普通读者默认只见业务名称、报告生成时/当前时点和四态，资源标识、版本链和重放证据放入“技术详情”，避免审计字段淹没正文。
- 用户切换“仅看问题”、章节筛选或核验范围后，从证据/Agent 审计页回链必须恢复原范围、章节、筛选和返回位置；相同根因可折叠显示数量，但底层逐项结果不得被合并删除。
- 从 RC-P9/RC-P12 深链 Agent 应用会话或结果审计详情后，回链恢复原报告版本和锚点，并按 Session/Context Binding/Run/Result 标识重新读取 Agent 权威状态与结果；不得用跳转前消息缓存或组件状态冒充权威记录。
- 同一报告/草稿精确版本内切换锚点时，每轮固定锚点快照；切换报告/草稿精确版本或证据包时，按 Agent 应用已确认合同形成新的 Context Binding 并默认派生新会话，旧会话只读。Agent Release、Skill 或工具版本变化不得冒充原运行重试。
- 报告助手默认上下文固定为报告生成时证据包；`[已裁决][D045][D047][RC-DE-012]` 只有用户显式选择“与当前数据比较”时才读取当前权威组合，返回后仍以报告快照为主上下文。比较默认作用于当前结构化事实项或当前章节，不对无绑定长文本自动形成正式差异。
- 从证据缺失或跨模块失败进入责任模块后，返回时恢复原生成请求或复核问题，不要求重新选择报告定义和对象。
- 所有列表区分首次为空、筛选无结果、读取失败和无可用资源，不用一个“暂无数据”覆盖不同原因。

### 4.2 页面结构与全局交互

S001 固定为以下自上而下结构，不向一期用户开放重排：

1. **场景与可信度栏：** 场景名称、仪表盘版本、当前范围、Published 语义版本，以及带 RC-DE 标签的可信度摘要。
2. **范围选择：** 集团 / 板块 / 单位分段切换；板块和单位支持搜索。板块名称按 D007 的 Published 语义展示。
3. **核心指标：** 七个 Metric 的当前范围结果、单位和口径入口。
4. **单位比较：** 明确选择两家或三家，展示组合结果、单体结果和差异。
5. **债务结构与机构分布：** 按 Published 属性和 Metric 展示结构，支持下钻借据。
6. **Rule 与行动协同：** 命中摘要、优先协商机构、只读决策运行摘要和标准 Action Request 入口。
7. **智能问数与 AI 洞察：** 固定问数入口、上下文问数入口和独立 AI 洞察区。

`[演示基线][待数据工程确认][RC-DE-010]` 当前板块选择器应能核对 10 个 Published 展示值：产业服务、产业金融、核技术、核能、核燃料、环保产业、集团及直管公司、境内新能源、境外新能源、数字化。该清单用于当前演示验收；后续页面仍以 Published 本体返回的板块范围为准，不在驾驶舱内维护映射。

全局规则：

- 切换范围会同步更新核心指标、结构、机构、Rule 和决策摘要；`[已收敛][D044][D045][RC-DE-003]` AI 洞察不自动伪装为同步更新，须按 T008、生成范围及业务 Owner 的新鲜度阈值显示。
- 集团和板块范围只浏览、比较和下钻；Action 请求只允许目标落到一个融资主体。
- 任意数值均可打开“口径与证据”，显示 Metric/Rule 名称、Published 语义版本、对象范围和必要证据；报告中心不展示本地计算步骤。

### 4.6 金融机构分布与问题机构

金融机构区分两种不可混淆的视图：

1. **总体融资分布：** 当前范围内按融资机构展示融资余额、笔数、机构类别和占比；支持银行/非银筛选及借据下钻。所用余额/占比必须来自 Published Metric 或获准语义查询视图。
2. **Rule 问题贡献：** 只在 Rule 命中时展示该 Rule 证据中的问题融资余额、贡献占比、问题融资加权成本、涉及借据数和前三家优先协商机构。

R01、R02、R03 的机构排序分别引用 Published Rule 中的高成本融资余额、浮动利率融资余额、短期债务余额贡献口径；R01 单一支路的特殊排序仍由本体 Rule 合同决定。报告中心不得把“总体余额最大机构”误称为“优先协商机构”，也不得由 AI 临时改变排名。

### 5.2 视觉与交互语义

- 确定性内容使用“指标/Rule/决策摘要”标签；AI 内容固定使用“AI 洞察”或“Agent 草稿”标签。
- 可信度异常以文字说明影响到哪些确定性区块；不得只改变颜色。
- AI 洞察的证据展开优先指向确定性资源；不能只引用另一段 AI 文本形成循环证据。
- 确定性数值与 AI 表述冲突时，页面保留冲突提示并以确定性资源为准；用户可请求重新生成，不能直接改 Metric。

| 证据完整 | 数据工程 | 完整、不完整、未知 | 指来源、处理、质量、发布和刷新证据；不等于报告证据包完整 |
| 重放能力 | 数据工程 | 具备重放条件、依赖不足、未知 | “具备”不等于已经执行或一致 |
| 重放核验 | 数据工程 | 未执行、排队中、运行中、一致、不一致、执行失败、未知 | 只有“一致”能说明本次数据侧重放一致；仍不证明 Metric/Rule 或报告已端到端复算；一期是否实际进入排队/运行及其结果态受 Q025 控制 |
| 端到端同口径复现 | 报告中心汇集各 Owner 证据后形成最终结论 | 未核对、核对中、一致、不一致、无法核对 | 数据工程证明数据侧，本体证明历史 Published 定义/兼容，报告中心证明结构化绑定与结果并形成最终聚合结论；任何单方证据都不能直接宣称完成 |

历史源不可重放不等于整份报告或全部检查一概“无法核验”：若固定证据包和结构化绑定完整，报告中心仍可核对冻结结果的内部一致性；仅依赖源重放或端到端复算的检查按受影响范围显示“无法核验”。发布时正式质量证据与核验时追加的后续质量发现必须分列，后续发现带标识、状态、确认时间和影响成员/字段范围，不回写生成时摘要。平台权限结果是与上述数据状态正交的一条轴，不得把“权限不足”写成版本不存在、内容不可访问或质量失败。

报告安全投影不得包含业务行、业务值、单位/机构/负责人名单、原始文件、失败样例、Metric 公式或 Rule 阈值。`[已裁决][D033][D050]` 一期演示保留全部历史且不提供删除入口；生产环境按 C030 的版本化策略分列在线、归档、可恢复、到期和特殊冻结状态，具体年限上线前配置，不默认永久在线或永久可重放。报告中心只提供正式报告引用与解除事实，不批准删除或替数据工程执行恢复。

### 6.10 RC-DE-012：报告快照与当前数据比较合同

`[已裁决][D045][D047][RC-DE-012]` 总控已通过 CR016 登记 C027，并在总控合同层关闭 RC-DE-012/AG-DE-010。报告中心拥有显式比较操作、比较运行和最终确定性记录；数据工程、本体管理、报告定义/业务 Owner 与平台授权边界分别提供其权威事实，Agent 应用只读解释。

比较页面必须分列四类身份：

| 身份 | 权威定义/Owner | 允许用途 | 禁止用途 |
|---|---|---|---|
| 报告生成时固定快照 | 报告中心固定的原报告、证据包、精确 Published/数据版本、T008 和版本绑定摘要 | 回答“报告当时”；作为比较左侧 | 被当前摘要、候选或新值覆盖 |
| 当前权威兼容组合 | 本体管理 C008/T019 当前正式组合；数据工程只给对应数据事实 | 满足比较门时作为右侧；准备新报告证据 | 仅凭质量通过、资产发布或刷新成功由数据工程/报告中心认定为当前 |
| 处理中或失败候选 | 数据工程提供到达、质量、发布、刷新、失败及恢复事实 | 提示“有更新正在处理/失败” | 作为当前业务值、参与正式数值比较或让 LLM 重算 |
| 上一可信证据 | 数据工程提供“上一已通过/已发布数据版本”；本体 C008 提供“上一权威服务组合”，两者分开 | 解释失败保护和历史服务关系 | 把从未被 T019 采用的版本称为上一服务版本；候选失败且 T019 未切换时把仍在服务的组合同时称为“上一版” |

候选失败时必须显示“候选失败，当前权威仍为 X”。每次比较固定当前状态摘要标识/版本、形成时间、C008/T019 证据引用和比较时间；再次比较形成新摘要和新比较记录，旧记录进入“比较陈旧”而不被后台刷新或覆盖。

完整比较门由以下 Owner 分担：

| 责任 | Owner | 必须确认 |
|---|---|---|
| 数据条件 | 数据工程 | 两侧精确数据版本/T008、发布时与核验时质量范围、刷新、保留和数据侧五维状态 |
| 当前采用与语义兼容 | 本体管理 | 当前/上一 T019、采用/切换时间，以及两侧 Object Type、Object 实例/集合范围、Property、Link、Metric、Rule 的 Published 语义版本、单位、关系、对象范围和口径相同或兼容 |
| 固定报告与比较结果 | 报告中心 | 左侧快照不变、结构化证据可访问、五个比较门、确定性比较状态和并列展示 |
| 业务门 | 报告定义或业务 Owner | 允许比较范围、新鲜度阈值及版本、质量警告是否阻断、重新生成触发条件 |
| 授权 | 平台既有授权边界 | 允许/拒绝结果及判定引用；报告中心只消费，不自建权限规则 |
| 差异解释 | Agent 应用 | 基于已固定比较上下文的独立解释运行 | 

五个比较门依次是：报告快照身份完整；当前侧确为仍生效 T019；本次范围内无质量硬失败/未知影响；本体可证明语义/单位/对象范围/口径相同或兼容；固定结构化证据可访问且用户获准。结果必须区分：

| 比较结果 | 适用条件 | 展示要求 |
|---|---|---|
| 可以比较 | 五门全部满足 | 并列精确双版本、T008、摘要/比较时间和确定性差异 |
| 可以比较但有警告 | 仍可比，但存在获准质量警告或按报告定义判为数据陈旧 | 明示警告、影响范围、阈值版本和判断时点；数据陈旧不自动等于无法比较 |
| 仅可做固定结果比较 | 历史数据不能重放，但报告冻结结构化结果完整且当前侧满足其余门 | 只将报告固定结果与当前 Published 结果并列，披露“历史源版本未重放”，不得宣称全链路复算 |
| 无法比较 | 身份冲突/不存在、当前无 T019/未就绪、质量硬失败或未知影响、语义不兼容/未知、范围/单位不齐、证据不完整或权限不足 | 只展示版本/状态差异、明确原因和获准恢复路径，不计算业务数值差异 |

四类结果必须落到每个结构化事实项或同一语义兼容组；整份报告和章节只汇总逐项结果，不能以单个不兼容项抹去其他可比项。当前 T019 在比较开始时固定，运行中不得混入后续切换版本。`比较陈旧`是报告中心拥有的 C027 记录上的正交标志、原因和发现时间，不覆盖比较当时的四类结果；Agent 会话只能披露其绑定的比较记录已陈旧，不能拥有或推进该状态。任何比较都不修改原报告、原证据包、原锚点或权威绑定；需要采用当前事实时必须创建新报告生成请求。

## 7. 报告定义与报告模板

### 7.1 报告定义完整合同

| 合同部分 | 必填内容 | 用户价值 | 缺失时表现 |
|---|---|---|---|
| 业务目的 | 报告回答的决策问题、使用情境和不适用范围 | 防止只因“有模板”就生成报告 | 不可启用 |
| 适用对象 | 场景、Object Type、单一对象/对象集合、时间或业务范围 | 明确报告针对谁 | 范围未知不可生成 |
| 读者与用途 | 目标读者、正式/内部草稿用途、允许的使用边界 | 决定复核和发布要求 | 不能形成发布规则 |
| 模板引用 | 精确模板版本及章节映射 | 固定章节骨架和版式 | 无模板时不可生成正式结构 |
| 证据范围 | 允许的 Object Type、Object 实例/集合、Property、Link、Metric、Rule、固定问数视图、决策摘要、其他获准定义证据和固定结果/评估证据；声明稳定证据槽位及其必填/可选规则 | 限定 Agent 只能使用经过批准的证据，并让长报告生成前即可检查章节证据是否准备齐全 | 证据范围为空或必填槽位无来源时不可生成 |
| 内容与绑定规则 | 允许的受控内容类型；章节/段落/指标卡/表格/图表/Rule 摘要/脚注/附件的稳定模板槽位；数值、比例、日期、Property 值、关系事实、Metric 结果、Rule 结论、需核验单元格和关键图表数据点等必须绑定类型 | 让 Agent 生成的长内容可以逐项追溯，而不是只对整篇正文做模糊问答 | 必须绑定类型无结构化事实项或证据引用时阻断确认/发布 |
| 事实项与覆盖门 | 计划事实项、适用事实项、已绑定、已核验、无绑定、无法分类、跳过和执行异常的统计规则；整份/章节/锚点核验范围及最低覆盖要求 | 区分“已核验部分正确”和“整份报告已完整核验” | 覆盖不足或运行部分完成时不得显示整份通过 |

| Agent/Skill 引用 | Agent、Skill 和配置版本引用 | 选择获准生成能力 | 不显示或维护提示词/Skill 正文 |
| 校验规则 | 必需章节、必需证据、数值一致性、版本完整性、禁用表述和缺失处理 | 在复核前发现可判定问题 | 未通过进入校验失败 |
| 展示与助手规则 | HTML/PDF 同源要求、稳定锚点要求、助手可用范围；自动核验解释策略为“不发起、按需发起或异常时发起”且必须使用独立 Agent Run；`[已裁决][D044][RC-DE-011]` 历史核验要求；`[已裁决][D045][D047][RC-DE-012]` 允许比较范围、新鲜度阈值及版本、警告阻断和重新生成门 | 保证阅读、伴读、核验和正式固定产物使用同一业务合同，并把确定性结果与 LLM 解释分开 | 未定义时不可发布一期正式报告 |

| 发布规则 | 允许发布的状态、产物命名、替代/撤回方式、读者范围 | 保证正式产物可追溯 | 不满足时停在待发布 |
| 版本与状态 | 定义版本、启用时间、停用状态和变更摘要 | 保证旧产物能解释原合同 | 已启用定义不可原地改 |

### 7.2 报告模板完整合同

模板只包含：模板名称、适用报告类型、章节层级、固定说明文字、指标卡/数据表/受控图表/Rule 摘要/证据引用/脚注/附件占位、页眉页脚等版式要求、输出样式和模板版本。模板必须为章节、段落、数值、表格单元格和图表声明稳定模板槽位及可形成定位锚点的规则；占位必须引用报告定义的证据槽位，不直接写 Metric 公式、Rule 阈值、临时业务公式、数据源路径、Agent 提示词或复核结论。模板只允许报告中心登记的受控内容组件，不接受 Agent 返回的任意 HTML、脚本或外部动态内容。

### 7.3 两者变更的影响

| 变更 | 是否形成新报告定义版本 | 是否形成新模板版本 | 对旧产物的影响 |
|---|---|---|---|
| 业务目的、适用对象、证据范围、Agent/Skill、校验、复核或发布规则变化 | 是 | 否，除非版式同时变 | 无；旧产物保留原定义引用 |
| 章节顺序、固定文字、占位和版式变化 | 仅当定义改绑新模板版本时记录新定义版本 | 是 | 无；旧产物保留原模板版本 |
| Metric/Rule 口径变化 | 报告中心不修改；定义需评估并显式改绑新语义版本 | 否 | 旧产物不变，新生成使用新获准版本 |
| Agent 提示词/Skill 变化 | Agent 应用形成新配置版本；报告定义显式改绑 | 否 | 旧草稿和产物保留原 Agent/Skill 版本 |

## 8. 报告生成、证据包、复核与正式产物

### 8.1 端到端流程

报告定义已启用 → 选择适用对象和生成范围 → 冻结证据目录、数据证据集合和模板证据槽位 → 校验证据完整性 → 向 Agent 应用提交生成请求 → 接收带源内容项身份和包内证据引用的结构化 Agent 草稿 → 报告中心校验内容类型与引用并形成受控草稿正文、精确内容版本、稳定锚点及“内容项—锚点—证据”正式绑定 → 形成事实项清单和覆盖统计 → 执行确定性自动核验 → 人工复核 → 退回重生成或有来源人工修订 → 再次核验并确认 → 同源形成 HTML/PDF → 发布正式报告产物 → 后续需要时重新生成新产物。

每一步都保留自己的身份和状态，不能用一个“报告生成成功”覆盖证据是否完整、草稿是否复核和产物是否发布。

### 8.2 报告生成请求

| 请求内容 | 一期功能规则 |
|---|---|
| 报告定义与模板 | 必须引用精确版本 |
| 场景与适用对象 | 使用平台场景编号和 Published Object 身份；不复制对象定义 |
| 证据范围 | 只能从报告定义允许范围选择；超范围证据被拒绝 |
| Agent/Skill | 只引用 Agent 应用提供的精确配置版本 |
| 内容与证据槽位 | 固定报告定义允许的内容类型、章节/模板槽位、必填证据槽位和生成范围；Agent 不得新增未获准业务公式或证据类型 |
| 版本 | Published 语义版本；`[已收敛][D044][D050][RC-DE-006][RC-DE-011]` 精确数据版本、数据截至时间及报告生成时版本绑定摘要标识/版本/形成时间 |
| 请求状态 | 已提交、固定证据中、证据缺失、可生成、生成中、生成失败、草稿已返回 |
| 幂等与重试 | 同一请求结果未知时先核对原生成记录；不得盲目重复并把新草稿冒充原草稿 |

### 8.3 生成证据包

`[已裁决][D021]` 证据包是 LLM 可使用内容的唯一边界，不是原始数据转储。

| 证据项 | 最小内容 | 允许用途 | 禁止用途 |
|---|---|---|---|
| Published 定义证据 | Object Type、Object 实例/对象集合、Property、Link、Metric、Rule 及必要 Action Type；每项稳定资源标识、报告生成时精确 Published 版本、定义、单位、范围、关系方向/端点、有效期和责任位置 | 生成忠实描述，并按 C026 重新定位历史定义 | Agent 改写公式/阈值/对象身份、重评 Rule，或用当前 Published 替代历史定义 |
| 固定结果/评估证据 | 稳定结果或评估证据标识与版本、Published 定义引用、对象实例或集合快照、筛选/参数、固定值或结论、单位、精度/舍入、空值/零分母规则、精确数据版本/T008、计算或评估时间和来源证据 | 为正式 Metric 结果、Rule 结论、Property/Link 事实、获准结构化视图及其他确定性结果提供可复核输入 | 由 Agent/Skill 临时计算正式数值、推导比例、重评 Rule，或仅凭定义重新构造报告值 |
| 对象集合证据 | 集合结果/证据标识、筛选规则及版本、成员数量、获权的成员稳定身份快照或可追溯引用、形成时间和精确数据版本 | 固定“当时包含谁”；当前比较时按报告定义区分固定原成员与同筛选规则当前成员 | 只保存一句筛选描述却无法还原历史集合，或静默隐藏成员变化 |
| 固定问数视图 | 视图版本、结构化结果、证据引用 | 复用已验证问数结论 | 把自由文本对话当正式证据 |
| 决策摘要 | 请求/提醒/确认/待办的获准摘要及状态时间 | 描述已发生决策进展 | 把未确认提醒写成已执行结果 |
| Agent 分析结果 | 已获准的分析结果、证据和确认状态 | 作为报告中的辅助解释 | 用一个 AI 结果证明另一个无底层证据的 AI 结果 |
| 数据证据集合 | 一项或多项精确 T006/T007/T008 及对应 C017 版本绑定摘要的标识/版本/形成时间、发布时质量、刷新和消费证据；每个固定结果说明实际使用的集合成员 | 支持长报告不同章节引用多个受治理数据版本，同时披露每项事实的真实时点 | 用单一“报告数据版本”掩盖多版本来源、通过摘要读取业务明细、动态取“最新摘要”或绕过本体 |
| 模板证据槽位 | 稳定模板槽位、允许内容类型、必填/可选、允许证据类型和章节归属 | 在 Agent 生成前约束章节与证据的可用组合 | 在草稿尚未产生前伪造最终内容绑定，或让 Agent 自行扩充未获准槽位 |
| 证据包元数据 | 证据包编号/版本、创建时间、创建者、报告定义版本、完整性校验和缺口 | 复核和追溯 | 生成后原地替换证据 |

证据包固定后不可原地增删。生成前固定的是“可用证据与模板槽位”，不是尚不存在的最终正文绑定；Agent 返回后由报告中心校验证据引用，才形成精确草稿/内容版本下的正式“源内容项—稳定锚点—一个或多个证据项”绑定。若证据缺失、版本冲突、范围变化或需要更新，创建新证据包并重新生成草稿；旧证据包继续关联旧草稿。

### 8.4 Agent 报告草稿

Agent 应用返回的不可变源草稿至少包含：草稿标识/版本、源内容项身份、父子层级和顺序、模板槽位、内容类型、结构化章节/内容块、逐项包内证据引用、未能生成的章节、警告、Agent Release Version、生成时间和原始运行入口；不得返回最终稳定锚点、可执行的任意 HTML、脚本或外部动态内容。报告中心校验内容类型、模板槽位和证据引用后，形成评审副本、精确内容版本、T044 稳定锚点及源内容项到锚点的映射。

每份草稿随后形成事实项清单，至少覆盖数值、比例、日期、Property 值、关系事实、Metric 结果、Rule 结论、需核验表格单元格、图表关键数据点，以及报告定义要求的其他事实和受治理计算结果。清单分列计划/适用、已绑定、无绑定、无法分类、跳过、已核验和执行异常数量；覆盖率与通过率分开。覆盖不足、存在未受治理计算或核验运行部分完成时，草稿可以查看，但不得冒充完整草稿或进入确认。

草稿不得自动成为正式报告。数值、Rule 结论、对象范围和决策状态必须能回到证据包；没有证据的表述标记“证据缺失”，不能靠措辞流畅性通过。

### 8.5 人工复核、退回与确认

复核工作区按章节和证据项检查：

1. 业务目的和适用对象是否一致；
2. 数值、单位、对象范围、Rule 和决策状态是否与证据一致；
3. 每个关键结论是否有证据引用；
4. `[已收敛][D044][D050][RC-DE-006][RC-DE-011]` 精确数据版本、数据截至时间、版本绑定摘要和发布时/核验时质量披露是否完整且未混写；
5. AI 推断是否被明确标识，是否越过确定性证据；
6. 事实项清单、内容证据绑定、核验运行和覆盖状态是否完整，是否存在未受治理计算；
7. 必需章节和发布声明是否完整。

`[本模块设计][一期最小实现]` RC-P9 同时提供固定“报告助手”。复核者可在“自动核验”中定位确定性差异，或在“报告问答”中请求有证据解释；助手输出只形成复核问题、打开证据或请求重新生成的依据，不能代替人工确认，也不能直接改写草稿数值。

| 复核动作 | 结果 | 约束 |
|---|---|---|
| 退回 | 草稿进入“已退回”，记录章节、问题类型、证据缺口和期望纠正 | 不在报告中心修改 Agent 提示词或 Skill；原草稿只读保留 |
| 人工修订 | 形成复核版本，保留 Agent 原文和逐段差异 | 数值/版本/Rule 修改必须重新选择证据或重新生成，不能无来源覆盖 |
| 确认 | 草稿进入“已确认待发布” | 所有硬校验通过，核验运行完整完成、覆盖完整且无未受治理计算；复核人、时间和结论留痕 |
| 取消确认 | 发布前可撤回确认并说明原因 | 修改内容后重新复核；旧确认不沿用 |

### 8.6 正式报告产物

正式产物必须记录：产物编号和版本、内容版本、场景、报告定义版本、模板版本、适用对象、Published 语义版本、`[已收敛][D044][D050][RC-DE-006][RC-DE-011]` 精确数据版本/T008/报告生成时版本绑定摘要标识与版本及数据证据集合、证据包版本、源内容项—稳定锚点—证据绑定、事实项清单和覆盖统计、确定性核验运行/结果引用、Agent Release/Skill/生成运行版本、原始草稿、人工复核版本、复核结论、HTML 阅读版、PDF 固定版/打印视图、稳定锚点清单、发布时间、发布者、状态和替代/撤回关系。核验时当前状态摘要、后续质量发现、重放核验、可选解释运行和当前比较记录作为追加追溯记录关联，不回写正式产物的生成时事实。

HTML 阅读版与 PDF 固定版/打印视图是同一正式报告产物的不同表现形态，必须共享报告编号、内容版本、证据链和发布状态。任何一方内容变化都必须重新生成、复核并形成新产物版本，不能分别维护或把重新渲染后的差异写回原产物。

已发布产物不可原地编辑。发现错误时：

- 若只需停止继续使用，标记“已撤回”并说明原因，内容和证据仍可追溯；
- 若需纠正，重新固定证据并生成/复核新产物，旧产物标记“已被替代”；
- 同一报告编号和内容版本可以同时对应 HTML/PDF 两种表现，但不允许覆盖该内容版本；任何纠错必须形成新内容版本和新产物版本，并保留替代关系，不能伪装为未发生变化。

### 8.7 重新生成

“重新生成”是受控新请求，不是改写旧产物：

| 情形 | 默认方式 | 产生的新资源 |
|---|---|---|
| 文案表述问题、证据未变 | 可沿用原证据包，提交新的生成请求 | 新 Agent 草稿版本 |
| 证据缺失或范围变化 | 创建新证据包后生成 | 新证据包 + 新草稿 |
| `[待数据工程确认][RC-DE-004]` `[已收敛][D044][D050][RC-DE-006]` 需要反映更新后的兼容数据 | 固定新的精确数据版本和证据包后生成 | 新证据包 + 新草稿 + 新正式产物 |
| `[已裁决][D045][D047][RC-DE-012]` 显式比较后确认当前兼容事实已发生有业务影响的变化 | 保留报告快照和比较结果，用户创建新生成请求并固定当前证据 | 新生成请求 + 新证据包；经复核发布后形成新正式产物 |
| 报告定义、模板或 Agent/Skill 变化 | 显式选择新版本并重新校验 | 新草稿；发布后形成新产物 |

重新生成必须保留完整来源链：`原报告/草稿精确版本与锚点 → 原 T049 或 C027 结果 → 报告问答/核验解释 → 复核问题 → 重新生成请求 → 新证据包 → 独立 Agent 生成 Run → 新不可变源草稿 → 新评审副本及事实项/锚点/证据绑定 → 新 T049 → 新正式产物及替代关系`。生成运行不得复用原报告生成运行或核验解释运行；新结果只回指旧资源，不覆盖任何旧内容或状态。

### 8.8 受控 HTML 报告展示与多形态一致性

`[本模块设计][一期最小实现]` 草稿复核页与正式报告阅读页采用同一阅读框架：**章节目录｜受控 HTML 报告正文｜报告伴读与核验助手**。该设计是系统内报告功能合同，不是 HTML 原型设计。

| 内容能力 | 一期展示规则 | 稳定定位与证据规则 |
|---|---|---|
| 章节与段落 | 支持多级章节、正文、受控强调和章节状态 | 每个章节、段落在精确草稿/内容版本内有稳定锚点 |
| 指标卡 | 展示名称、值、单位、范围、时点和证据入口 | 数值锚点必须关联结构化 Metric/Property 证据绑定 |
| 数据表 | 展示获准列、行、汇总、单位和脚注 | 表格及每个需核验单元格有稳定锚点；`[已裁决][D045][D047][RC-DE-012]` 不得在阅读时动态换成当前数据 |
| 受控图表 | 只展示报告模板允许的固定图表内容、范围、单位、图例和证据 | 图表整体及关键数据项可定位；图表值与报告固定证据同源 |
| Rule 摘要 | 展示 Rule 名称、版本、评估时间、触发分支、命中证据和结论 | Rule 结论锚点绑定结构化 Rule 证据，不由 LLM 重评 |
| 证据引用与脚注 | 展示来源身份、版本、时点、限制和打开入口 | 引用与脚注锚点能回到获准证据，不显示无权内容 |
| 附件 | 展示附件身份、版本、适用章节和可用状态 | 附件及其引用位置均可定位；权限不足或不可读时明确受限 |

稳定定位采用“报告编号或草稿标识 + 精确内容/草稿版本 + 锚点”的组合语义。新版本可以形成新的锚点集合，但旧锚点必须继续定位旧内容，不能静默指向新版本的其他位置。助手回答、核验结果、复核问题和证据深链均引用该组合。

同一正式报告产物同时提供：

1. 系统内受控 HTML 阅读版，承担目录、定位、证据展开和报告助手交互；
2. PDF 固定版和打印视图，承担固定交付、离线阅读和打印；
3. 两种表现共享同一报告编号、内容版本、证据包、章节/数值/Rule 结论、脚注和完整证据链，分页差异不构成新的内容版本。

发布完成门要求 HTML 与 PDF 均来自同一已确认内容版本。任一形态形成失败时，不得把不完整产物标记为“已发布”。已发布 HTML/PDF 必须冻结，不随新数据、新模板或后续重新渲染原地变化；该冻结由报告中心自身保证，不以底层历史数据是否可重放为前提。纠错和更新必须形成新内容版本、新产物及替代关系。Agent 只能返回结构化报告内容，不得生成或执行任意 HTML、脚本或外部动态内容。DOCX 默认列为后期能力；只有 S004 后续资料明确要求 Word 正式交付时，才在同一主文档中增量纳入一期并补齐同源一致性合同。

### 8.9 报告伴读与数据核验助手（Report Copilot）：报告问答

`[本模块设计][一期最小实现][已裁决][D042][RC-X-009][已裁决][D043][D047][RC-X-010]` RC-P9 与 RC-P12 固定显示“报告助手”侧边页签，内部固定为“报告问答”和“自动核验”两个子页签。用户可选择当前章节、段落、数值、单元格、图表或整份报告；无论选择范围大小，上下文事实根始终是当前草稿/产物版本绑定的证据包。每轮请求固定 Agent Release Version、Report Context Binding ID/Version 和一个或多个稳定锚点快照。

| 问答结果组成 | 一期要求 |
|---|---|
| 回答与范围 | 直接回答问题，并说明基于当前锚点、章节还是整份报告；解释、归纳和建议必须与确定性事实分开 |
| 报告位置 | 显示精确草稿/内容版本和一个或多个稳定锚点，可定位原文 |
| 权威证据 | 显示证据项、Object Type/Object 实例或集合、Property、Link、Metric、Rule 及必要 Action Type 的稳定标识、生成时精确 Published 版本和可打开入口；不得只引用报告自然语言 |
| 版本与可信度 | 显示报告定义/模板/证据包/Published 语义版本；`[已裁决][D044][RC-DE-011]` 默认显示版本绑定摘要，核验时另列当前状态摘要、数据侧五维状态和端到端同口径复现状态 |
| Agent 身份与状态 | 显示生成时间、Agent Release Version、Session/Context Binding/Run/Result 标识与版本、会话/运行/结果权威状态、回答确认状态和 Agent 应用稳定审计入口 |
| 限制 | 证据不足、权限不足、版本冲突或 `[已裁决][D044][RC-DE-011]` 质量异常时，明确说明受限范围、不能下结论的原因和获准下一步，不生成猜测性数值、比例、日期或 Rule 结论 |

报告中心只保存并展示 Agent 资源标识，回答正文、解释和状态按标识从 Agent 应用重读；回链或页面恢复后不得用本地消息缓存冒充权威结果。回答“已确认可作复核参考”只属于 Agent 回答确认轴，不等于确定性核验通过、草稿确认或报告发布。

默认问答只基于报告生成快照。助手不能把回答写回报告正文，也不能把回答当作新的正式证据；可用动作仅为打开证据、创建复核问题、请求重新生成，以及 `[已裁决][D045][D047][RC-DE-012]` 显式发起第 8.11 节的独立当前比较。草稿仍通过人工复核动作修改；正式报告只能通过新请求、新证据包、新草稿和新产物纠正。

### 8.10 自动核验合同

自动核验是现有报告定义校验、证据包校验和草稿复核的确定性扩展，不形成第二套事实口径。数值、比例、日期和 Rule 结论在报告生成阶段建立结构化证据绑定；报告中心必须先独立执行确定性比对并形成四态。只有用户需要业务可读解释时，才另行发起 Agent 核验解释运行；LLM 只解释差异、归纳影响和提出处理建议，不参与正式指标或 Rule 计算。未发起解释、解释部分完成或解释失败均不得阻断已经具备证据的确定性核验，也不得改变四态。

#### 8.10.1 核验请求、范围、运行与覆盖

长报告核验请求必须固定：核验运行标识/版本、精确草稿或报告内容版本、事实项清单版本、内容证据绑定版本、报告定义核验规则版本、证据包版本、数据证据集合、发起者和发起时间。范围只允许三类：整份报告、一个或多个章节、一个或多个稳定锚点；整份或章节操作本质上冻结其当时的事实项清单，不以运行期间新增内容扩张范围。

核验必须分开三条状态轴：

| 状态轴 | 一期状态 | 解释与门禁 |
|---|---|---|
| 核验运行状态 | 未发起、排队中、运行中、已完成、部分完成、运行失败 | “部分完成”保留已完成结果，但不得显示整份报告通过；运行失败不把未执行单元伪装成无法核验 |
| 覆盖状态 | 完整、受限 | 显示计划、适用、已完成、待处理、执行异常数量；覆盖受限时只能说明已完成范围，不得外推整份结论 |
| 检查项结果 | 通过、警告、失败、无法核验 | 只对已完成且适用的单项形成；不适用是独立适用性字段，不是第五种结果；执行异常也不是“无法核验” |

每个核验运行必须确定性汇总报告级、章节级和检查类型级的计划数、适用数、已完成数、待处理数、执行异常数，以及四态数量。页面采用“报告级摘要 → 章节级汇总 → 锚点级问题明细”的渐进披露；默认支持仅看失败/警告/无法核验，点击问题返回正文锚点并恢复原范围和筛选。相同根因可以分组显示数量，但底层逐事实项结果和证据引用不能合并丢失。所有计数、分类和优先级由报告中心确定性形成，LLM 只能解释既有汇总。

核验中断后允许仅对失败或待处理单元重新核验，但必须新建运行并引用原运行、原范围和被选单元，不能覆盖旧结果。只有运行“已完成”、覆盖“完整”且所有必需检查项均有结果时，才允许计算整份汇总状态；否则统一显示“核验未完整”，并可附“已完成范围内未发现失败”，不得简写为“通过”。

#### 8.10.2 检查项四态

| 状态 | 判定语义 | 对草稿/正式产物的影响 |
|---|---|---|
| 通过 | 适用的必需证据可访问，确定性比对全部满足 | 该检查项可进入后续复核；不等于整份报告已确认 |
| 警告 | 核验已完成，但存在获准舍入、`[已裁决][D044][RC-DE-011]` 非阻断质量/新鲜度或披露风险 | 必须显示影响并按报告定义决定是否需处理；不得静默折算为通过 |
| 失败 | 已确定与权威证据、版本兼容关系或硬性报告规则冲突 | 草稿确认和新产物发布必须阻断；正式产物只创建问题，不原地修改 |
| 无法核验 | 因证据缺失、权限不足、`[已裁决][D044][RC-DE-011]` 历史版本不可访问、版本关系无法判断、质量不足或无结构化绑定而无法可靠判断 | 不得算作通过；必需检查项阻断确认/发布，其他项按报告定义进入人工复核 |

在运行与覆盖均完整时，页面单一汇总状态的确定性优先级为“失败 > 无法核验 > 警告 > 通过”，同时保留全部逐项结果，不能用汇总覆盖细节。Agent 会话/运行/回答/解释状态按第 6.7 节另轴显示：“Agent 失败”不是报告核验“失败”，“受限完成/部分完成”也不能自动映射为“无法核验”；是否无法核验只能由报告中心根据确定性证据缺口按检查项判定。

#### 8.10.3 一期检查项

| 检查项 | 确定性核验内容 | 典型状态判定 |
|---|---|---|
| 证据完整性 | 报告定义必需证据、证据包条目、结构化绑定和正文锚点是否齐全且在报告中心获准范围内可读 | 生成时必需绑定缺失为失败；因平台权限或报告证据包不可读为无法核验；历史源数据不可重放本身不等于报告冻结证据不完整 |
| 报告数值与绑定证据一致性 | 数值、比例、日期与报告生成时固定绑定证据的值、单位、精度/舍入、对象范围和时点是否一致 | 超出获准容差为失败；仅存在获准舍入差为警告；固定绑定完整时可核对，即使源数据尚未重放 |
| 语义一致性 | Object Type/Object、Property、Link、Metric、Rule 及必要 Action Type 的稳定标识、名称、单位、方向/端点、筛选范围和时间范围是否与生成时精确 Published 定义一致 | 身份、单位、关系端点或范围冲突为失败；仅显示别名/弃用提示且身份与历史定义一致可警告；本体证据无法定位为无法核验 |

| 报告内部一致性 | 摘要、正文、表格、受控图表、脚注和附件中的同一结构化事实是否一致 | 确定冲突为失败；无权或不可读附件为无法核验 |

#### 8.10.4 单项结果与 LLM 解释合同

每项确定性核验结果必须包含：核验运行/范围/规则版本、检查项、适用性、执行状态、四态结果、报告编号或草稿标识、精确内容/草稿版本、源内容项和事实项标识、内容证据绑定标识、一个或多个稳定锚点及类型、问题说明、当前报告内容、权威证据标识及获准入口、Object Type/Object 实例或集合/Property/Link/Metric/Rule/必要 Action Type 的稳定标识与生成时精确 Published 版本、证据包版本、数据证据集合引用、精度/舍入/容差规则、核验时间、影响范围、建议处理方式和确定性比对结果。`[已裁决][D044][RC-DE-011]` 还必须引用版本绑定摘要和核验时当前状态摘要的标识/版本/形成时间、精确数据版本/T008、发布时与核验时质量、五维数据侧状态、端到端同口径复现状态及各自责任位置。

报告定义可选择“不发起、按需发起、仅异常时发起”LLM 解释策略。实际解释必须新建独立 Verification Explanation Agent Run/Result，固定引用原 T049、精确报告范围和 Context Binding；其 Run 标识不得等于报告生成 Run，也不得用生成运行中的自评文本冒充独立核验。Agent Release Version、Session/Context Binding/Run/Result 标识与状态仅在已发起解释时必填，并与确定性结果分栏。解释未发起、失败、部分完成或输出不合格时仍保留原四态，不得用解释覆盖、降级或升级确定性结论；叙述性疑点只能形成“AI 建议”或复核问题，不能直接把确定性检查改为失败。

报告中心可以把结果转换为复核问题，并绑定原核验结果引用；不得复制 Agent 会话或运行记录。权限不足时只显示受限原因和获准处理路径，不泄露证据值。发布时固定当次核验结果引用；发布后再次核验产生新的关联结果，不改写已发布报告或原核验记录。

### 8.11 报告快照与当前兼容数据比较

`[已裁决][D045][D047][RC-DE-012]` “与当前数据比较”必须由用户显式发起，不能作为默认问答的隐式取数方式，并完整执行第 6.10 节的四类身份、五个比较门、四类比较结果和多 Owner 合同。

报告追溯、固定证据核验、历史数据重放和当前比较共用同一证据链，但回答不同问题，不是四套重复页面：

| 能力 | 回答的问题 | 是否读取当前数据 | 一期边界 |
|---|---|---|---|
| 报告追溯 | 这段内容当时用了什么定义、固定结果、数据版本和生成/复核链 | 否 | 始终可从报告位置打开；只读展示 |
| 固定证据核验 | 报告显示是否与其生成时冻结证据一致 | 否 | 报告中心确定性执行，是一期必需能力 |
| 历史数据重放 | 旧数据能否按旧受治理口径重新执行并一致 | 否 | 显示 C017 五维事实；真实执行深度受 Q025 控制，不影响前两项 |
| 报告快照—当前比较 | 报告当时的结构化事实与当前 T019 兼容事实有何差异 | 是，必须显式发起 | 形成独立 C027/T048 记录，不改写报告或历史核验 |

| 比较阶段 | 一期规则 |
|---|---|
| 默认状态 | 只显示并回答报告生成时固定快照；正文、证据包、版本绑定摘要和已发布内容均保持不变 |
| 独立比较上下文 | 创建新的比较上下文和比较记录，固定本次当前状态摘要标识/版本/形成时间、C008/T019 证据和比较时间；不替换默认 Report Context Binding |
| 四类身份 | 分列报告生成快照、当前 T019、处理中/失败候选、数据侧上一已通过/发布版本与本体上一权威服务组合；候选不进入数值比较 |
| 比较单元 | 仅选择已有结构化证据绑定的事实项或语义兼容组；整份/章节操作只是批量冻结其事实项；叙述文字只可由 Agent 解释关联事实变化，不能形成正式数值差异 |
| 确定性结果 | 每个事实项或兼容组分别形成“可以比较、可以比较但有警告、仅可做固定结果比较、无法比较”；报告级/章节级只汇总数量；数据陈旧不自动等于无法比较，历史源未重放不得冒充全链路复算 |
| Agent 解释 | 仅在用户需要时基于固定比较上下文发起独立解释运行；解释失败不改变确定性比较结果 |
| 后续动作 | 用户可打开双方证据、创建复核问题或请求重新生成；请求重新生成必须创建新请求和新证据包，旧报告保持冻结 |

一次比较开始时固定当前 T019、C017 当前状态摘要、语义兼容证据和比较时间，运行中不得混入随后采用的版本。后续当前组合或摘要变化时，旧比较记录保留原四类结果并追加“比较陈旧”标志、原因和发现时间；再次比较形成新记录，不覆盖旧记录。助手不能决定哪个版本成为权威绑定、不能修改本体或数据、不能把比较结果直接发布，也不能执行 Action。

## 11. 关键用户旅程

### 11.1 旅程一：从平台入口进入 S001 并定位问题

1. 用户从候选平台一级仪表盘入口选择 S001。
2. 页面显示仪表盘版本、集团范围、Published 语义版本和带 RC-DE 标签的可信度信息。
3. 用户查看七个集团 Metric，下钻到某板块，再选择一个单位。
4. 用户打开单位 Rule 命中，查看阈值、机构贡献和借据。
5. 页面保持范围上下文，用户可进入智能问数或决策中心后返回。

失败分支：对象/Metric 未就绪显示语义资源缺口；可信度异常按第 10 章提示；决策摘要失败不影响确定性 Metric 浏览。

### 11.2 旅程二：比较两家/三家单位

1. 用户进入单位比较，选择 2 家或 3 家。
2. 系统按稳定身份去重，将对象集合提交给 Published Metric。
3. 页面并列单体指标和组合指标，明确组合成本不是单位成本简单平均。
4. 用户从差异进入某单位的结构、机构和 Rule 证据。

失败分支：重复单位被阻止；不存在或余额为零分别解释；任何本地临时计算都判定失败。

### 11.3 旅程三：从 Rule 证据发起受控 Action

1. 用户在单一单位范围查看命中 Rule 和前三家优先协商机构。
2. 页面核对来源类型/来源记录、发起者、单一主体、已发布 Action Type、Rule 引用/版本/评估时间/触发分支/命中证据、Metric 快照、双版本、业务时点和行动建议上下文。
3. 用户点击“发起融资优化建议”。
4. `[已裁决][D037][D038]` 报告中心只提交标准 Action Request，并等待决策中心返回请求标识。
5. 成功后打开决策中心的 Action Request 详情；提醒生成、确认/拒绝、负责人分配、待办创建和状态更新均不在报告中心完成。
6. 用户从决策中心回链后恢复原单位和证据位置，报告中心重新读取 C019 摘要。

失败分支：若决策中心返回已有请求则打开该记录；结果未知时报告中心不把请求写成成功，也不自行设计重试去重或失败纠正流程；任何情况下不得直接创建待办。

### 11.4 旅程四：查看或重新生成 AI 洞察

1. 用户在集团、板块或单位范围请求洞察。
2. 报告中心固定获准证据并向 Agent 应用发起请求。
3. `[已收敛][D044][D045][D050][RC-DE-003][RC-DE-006]` Agent 结果返回后显示证据、版本、生成时间、新鲜度和确认状态。
4. 用户查看证据；结果陈旧或被拒绝时请求重新生成。

失败分支：证据缺失不生成；确定性资源与洞察冲突时以确定性资源为准并保留冲突说明。

### 11.5 旅程五：从报告定义到 Agent 草稿

1. 维护者创建报告定义，选择场景、适用对象、模板、证据范围和 Agent/Skill 引用。
2. 校验业务目的、证据、复核和发布规则后启用定义。
3. 发起人选择对象和范围，冻结证据目录、数据证据集合、生成时版本绑定摘要和模板证据槽位。
4. 前置证据完整后向 Agent 应用发起生成；Agent 返回结构化章节、源内容项身份和包内证据引用。
5. 报告中心校验后形成精确草稿/内容版本、稳定锚点、正式内容证据绑定、事实项清单和覆盖统计，再执行确定性核验；运行与覆盖完整且未触发阻断时进入“草稿待复核”。

失败分支：定义未启用、证据缺失、版本冲突或 Agent 失败均停在对应状态，不产生正式产物。

### 11.6 旅程六：人工复核、退回、确认和发布

1. 复核者逐章节核对草稿与证据。
2. 对证据不足或表述错误的章节退回，原草稿保留。
3. Agent 返回新草稿或复核者作有来源的人工修订，系统保留差异。
4. 全部硬校验通过后人工确认。
5. 发布形成固定报告产物并进入产物库。

失败分支：无来源数值修改被阻断；发布失败先核对是否已有正式产物，再决定重试，不能制造重复产物。

### 11.7 旅程七：新数据到达后的仪表盘与报告行为

1. `[待数据工程确认][RC-DE-004]` `[已收敛][D049][RC-DE-009]` 新候选进入处理或失败期间，S001 继续展示 T019 尚未切换的当前权威组合，并另列候选状态；只有历史服务关系才称“上一权威组合”。
2. `[待数据工程确认][RC-DE-004]` 新版本兼容且消费就绪后，同一仪表盘版本更新确定性内容。
3. `[已收敛][D044][D045][RC-DE-003]` 原 AI 洞察根据证据变化标记陈旧，不自动改写。
4. `[已收敛][D044][D050][RC-DE-006]` 已发布报告仍绑定原数据版本和证据包；如需反映新事实，发起重新生成并发布新产物。

### 11.8 旅程八：在草稿复核页伴读和自动核验

1. 复核者打开 RC-P9，页面同时显示章节目录、受控草稿正文和固定“报告助手”。
2. 用户选择一个数值、表格单元格或 Rule 结论锚点，在“报告问答”中询问来源；报告中心提交精确草稿版本、每轮锚点快照、证据包和权限判定引用，Agent 应用形成/恢复 Session 与 Context Binding。回答回指 Object Type/Object、Property、Link、Metric、Rule/必要 Action Type 的稳定标识和生成时精确 Published 版本。
3. 用户切换“自动核验”，选择整份、章节或锚点范围；页面顶部显示计划/适用/已完成/待处理/执行异常及四态数量，中层按章节汇总，明细回到锚点。报告中心独立执行第 8.10 节八类确定性检查；此时不要求存在 Agent 解释运行。
4. 若运行部分完成或覆盖受限，页面只说明已完成范围并允许对失败/待处理单元新建恢复运行，不显示整份通过。用户需要业务可读解释时，再把 T049 引用和固定上下文提交 Agent 应用形成独立解释运行；该运行不得复用报告生成 Run，解释失败或部分完成不改变四态。
5. 用户把警告、失败或无法核验项转换为复核问题，打开证据，或退回并请求重新生成；来源链保留原锚点、T049、Answer/Explanation、复核问题和新请求。
6. 新草稿形成后建立新的内容绑定、事实项清单、Context Binding 和默认新会话，再重新核验；旧会话只读。只有必需范围覆盖完整、运行完整完成、必需项不存在失败/无法核验且完成其他人工复核，才能确认草稿。

失败分支：证据不足、权限不足、历史语义无法定位、版本冲突或 `[已裁决][D044][RC-DE-011]` 质量/数据侧状态异常分别显示限制和责任位置；不得让 LLM 猜测数值、日期、比例或 Rule 结论，也不得由助手直接修改草稿。Agent 输入/输出不合格、失败或取消只影响 Agent 运行，不覆盖确定性结果。

### 11.9 旅程九：阅读正式 HTML 报告并伴读核验

1. 读者从 RC-P10 打开 RC-P12，看到章节目录、受控 HTML 正文和固定“报告助手”，并可打开同一产物的 PDF 固定版或打印视图。
2. 用户从目录或助手结果定位章节、段落、数值、单元格或图表锚点；旧版本锚点始终定位旧内容。
3. 用户提问时，助手默认只基于报告生成时固定证据回答，显示报告位置、权威证据、完整版本链、版本绑定摘要、Agent Session/Binding/Run/Result 和限制；报告中心按标识重读，不保存消息/状态副本。
4. 用户按整份、章节或锚点执行自动核验；报告级摘要、章节级汇总和锚点级结果都关联当前正式产物精确版本。需要解释时另起 Agent 运行；无论解释结果如何，正式页只能打开证据、创建复核问题或请求重新生成。
5. HTML 与 PDF 的报告编号、内容版本、数值、Rule 结论、脚注和证据链一致；伴读和核验均不改变两种固定形态。

失败分支：任意 HTML、脚本或外部动态内容被阻断；HTML/PDF 任一形态形成失败时产物不能标记已发布；助手无修改、发布或 Action 控件。

### 11.10 旅程十：显式比较当前数据并请求重新生成

1. 用户在 RC-P12 阅读历史报告，默认问答继续使用报告快照。
2. `[已裁决][D045][D047][RC-DE-012]` 用户显式选择“与当前数据比较”。
3. `[已裁决][D045][D047][RC-DE-012]` 页面创建独立比较上下文，固定本次当前状态摘要标识/版本/形成时间、C008/T019 证据和比较时间，并列报告快照、当前 T019、处理中/失败候选及数据侧/本体侧两类上一可信证据。
4. 五个比较门完成后，报告中心按每个结构化事实项或语义兼容组形成四类结果，章节/整份报告只汇总；无绑定叙述不形成正式数值差异，候选不参与比较，历史源未重放时只允许固定结果比较且不能声称全链路复算。
5. 用户需要解释时，Agent 应用基于本次固定比较上下文形成独立解释运行；LLM 只解释差异，不改变确定性比较状态。
6. 用户认为差异需要纳入正式内容时，创建复核问题或新生成请求；新请求固定新证据包，经复核后形成新产物。
7. 原 HTML/PDF、证据包、锚点和内容版本始终冻结。当前状态变化不改变旧比较的逐项结果，只追加“比较陈旧”标志；再次操作产生新比较记录。

### 11.11 旅程十一：历史报告核验与可复现诚实降级

1. 用户在 RC-P12 对一份旧正式报告发起自动核验；报告中心先核对自身冻结内容、结构化绑定和版本绑定摘要。
2. `[已裁决][D043][D047][RC-X-010]` 本体管理按稳定资源标识和报告生成时精确 Published 版本返回“证据已定位/无法定位”、权威语义事实和责任位置；不读取正文或生成四态。
3. `[已裁决][D044][RC-DE-011]` 数据工程形成新的当前状态摘要，分列版本定位、内容访问、证据完整、重放能力和重放核验。重放状态统一为未执行、排队中、运行中、一致、不一致、执行失败、未知；`[待用户裁决][Q025]` 只决定一期是否真实进入排队至结果分支。
4. 报告中心按检查项形成四态：冻结证据完整时继续核对内部一致性；只有依赖历史数据重放或端到端复算且证据不足的项目显示“无法核验”，不把整份报告一概降级。
5. 只有数据侧、本体历史 Published 证据和报告结构化绑定共同支持时，才可披露“端到端同口径复现一致”；任一单方结果都不得替代联合结论。

失败分支：版本不存在、身份冲突、历史语义无法定位、内容不可访问、重放依赖不足、权限不足和质量异常分别显示，且不得回退当前/相似版本。无论 Q025 如何裁决，一期都必须支持冻结证据核对，以及“未执行、依赖不足、仅元数据可定位、引用无效、影响范围未知”等诚实降级；D050/C030 不承诺永久在线或永久可重放。
